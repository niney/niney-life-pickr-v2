# hiking — 등산(/hiking: 100대 명산·전국 주요 봉우리·국립공원 공식 코스 — 코스 상세·산행 조건·추천·GPX)

**신규 토픽 — 2026-10-25~26 등산 1~10차(`72c9982e`·`a77d1ac6`·`54eb0cb8`·`00804516`·`ffd2d827`·`bff8ca7c`·`7eb02951`·`6da860c7`·`0e38c4ee` + 9차 보강·10차는 작업 트리, 커밋 전)**: 사이드바 '일상지도' 다음에 독립 메뉴 **'등산'(`/hiking`)** 이 생겼다. 1차(`72c9982e`, 10-25)가 한국등산트레킹지원센터 **100대명산 GPX zip(data.go.kr 15098177, 코스 607)** 을 압축을 풀지 않고 읽어 정리(고도 튐·조각 잇기·방향)한 뒤 산림청 명산등산로·등산트레킹 POI·산정보 사진과 합쳐 `Hiking*` 표에 전량 교체하는 `load:hiking` 과 공개 API 4개·웹 지도/산/코스 화면을 놓았다. 2차(`a77d1ac6`)가 **Tobler 보행 함수 기반 예상 시간·난이도 3단계**·코스 이름 보강·이정표 '가는 길·온 길', `54eb0cb8` 이 맛집과 같은 데스크톱 3칸/폰 시트 틀, 3차(`00804516`)가 **산행 조건**(오늘·내일·모레 날씨·가장 높은 곳 추정 기온·대기·산불위험예보 15084817·해 지기 전 하산), 4차(`ffd2d827`)가 **"오늘 어느 산" 추천**과 코스 '가는 법·주변'을 붙였다. 5차(`bff8ca7c`)가 **전국 주요 봉우리 GPX(15108086, 봉우리 4,492)** 를 100대 명산에 합치거나 따로 산으로 두고, 6~8차(`7eb02951`)가 등산로 망을 코스로 잇고(망 코스 5,464) 화장실·주차·가파른 구간·브이월드 전국 등산로 배경 선·추천 전국화를, `6da860c7`(10-26)이 지도 산 마커 크기·순서를, 9차(`0e38c4ee`, 10-26)가 **행정안전부 산행안전지도(safetydata) 국립공원 공식 코스 199·경계 22·탐방지원센터·대피소**를 넣었다. 작업 트리(커밋 전, 10-26)에는 9차 보강(**예상 시간 재보정 1.12·360·600 → 1.35·180·1500**, 근처 GPX 도 없는 공식 코스 41개에 **SRTM 지형 고도**(`hiking-dem.ts`), 같은 길 공식 문구가 코스와 반대 방향이면 `reversed`)과 10차(**GPX 내보내기 `GET /hiking/courses/:id/gpx`**, 국립공원 탐방로 통제·입산 시각 링크, **앱 등산 화면 `apps/mobile/app/hiking`**, 웹 `hikingFormat` 순수 함수 → `@repo/shared` `hiking/hikingFormat.ts`, 앱 `TransitMapView.fitToCoords` 의 `belowInset`)이 있다. 로컬 적재(9차 기준): **산 3,879 · 코스 9,435 · 지점 38,617 · 코스 지점 67,102**. 9커밋은 2026-10-26 git 기준 원격 `origin/main` 에 있다(`0e38c4ee` 까지). 운영 배포·적재 여부는 문서에 기록이 없다(PLAN §운영 배포는 절차만). 설계·실측·결정의 정본은 [PLAN-hiking.md](../../docs/PLAN-hiking.md).

## Purpose [coverage: high — 12 sources]

"어느 산의 어느 길로, 몇 시간 걸려, 오늘 가도 되나, 어떻게 가나" 를 **비로그인 공개**로 답한다([HikingPage.tsx](../../apps/web/src/routes/HikingPage.tsx) 머리 주석).

- **산 목록** — 100대 명산 + 전국 주요 봉우리(코스가 있는 곳) 3,879곳을 한 번에 받아 화면에서 검색·권역 6칩(수도권·강원·충청·전라·경상·제주, `HIKING_REGION_GROUPS`)·정렬(기본 **가까운순** — 내 위치, 안 되면 서울 시청 기준 / 높은순 / 이름순)한다. 60곳씩 '더 보기'(`HIKING_LIST_PAGE`). 100대 명산 배지·국립공원 이름·합친 봉우리 이름으로도 찾는다.
- **산 상세** — 사진(적재 때 받아 둔 사본)·높이·소재지·국립공원 배지·선정 이유·개관·산림청 안내 코스 원문·이 산의 봉우리·코스 카드(난이도·예상 시간·형태, 국립공원 공식 코스가 먼저 — 안내 소요시간·난이도 원문)·이어진 봉우리.
- **코스 상세** — 거리·예상 시간·난이도·오르막·내리막·최고 고도, 방향별 시간·난이도 까닭, 끊김 안내, 고도 그래프(험한 노면 띠·가파른 구간 주황 칠, 가리킨 자리를 지도에), 코스 지점 목록(갈림길은 가는 길·온 길, 센터·대피소 연락처), 국립공원 공식 코스 칸(원문 그대로), **산행 조건** 카드, **가는 법·주변**, **GPX 받기**(작업 트리).
- **추천** — 출발 위치·날짜(오늘~모레)·출발 시각·산행 시간(3시간 안/반나절/하루)·난이도·이동 수단(차/대중교통)으로 산·코스 순위와 이유 문장·주의할 점.

### 적재 조립 단계 ([hiking-master.service.ts](../../apps/friendly/src/modules/hiking/hiking-master.service.ts) `buildHikingRows`, [load-hiking.ts](../../apps/friendly/scripts/load-hiking.ts))

네트워크는 스크립트가, 조립은 순수 함수가, 쓰기는 `replaceHiking` 이 한다(파일 머리 주석).

1. **GPX 읽기·정리**([hiking-gpx.ts](../../apps/friendly/src/modules/hiking/hiking-gpx.ts), 순수 함수) — `parseGpx` 는 정규식 해석(트랭글 1.1, `trk` 이름 없음·`time` 전부 같은 값). **고도 튐**(`cleanElevations`): 직전 유효 점 대비 경사 1(45°, 10m 미만은 10m 로)을 넘는 점을 버리고 보간 → 이동 중앙값(창 5) — 누적 상승 최대 9,707m(백운산(포천)) → 2,011m. **조각 잇기**(`stitchPieces`, `JOIN_GAP_M` 30m) — 끝점이 가장 가까운 조각을(필요하면 뒤집어) 잇고 30m 안이면 합침, 남은 끊김은 거리·시간에 넣지 않는다. **방향** — 편도이고 시작이 끝보다 30m 이상 높으면 통째로 뒤집음(108코스), `LOOP_M` 300m 안이면 원점회귀. 선은 4m 단순화 encoded polyline(조각별), 고도 프로필 20m(`PROFILE_STEP_M`), 노면 범위 → 거리.
2. **형태·이동 분·가파름**(2차) — `shape` = loop / summit(코스 최고점에서 끝남) / traverse. `moveMinutes` 가 조각마다 20m 표본으로 Tobler 이동 분을 시작→끝(`moveMin`)·끝→시작(`moveRevMin`) 둘 다 저장하고, `steepestPct` 는 조각 안에서만 가장 가파른 500m 평균 경사(끊김을 건너 재면 141% 가 나왔다).
3. **산·지점** — 명산등산로 100(이름 끝 괄호를 떼고 GPX 폴더와 맞춤 `matchGpxFolder`, 방장산은 산정보로 코드 보충 457900601) + POI 병합: GPX `sym` 과 API `poiId` 는 **다른 번호 체계**라 `gpx:`/`api:` 접두, 같은 분류 10m 안이면 합침(`both`), GPX 안 같은 자리 다른 번호 227건은 하나로. 코스 지점 = 그 GPX 지점(선 200m `COURSE_POI_M`) + API 에만 있는 지점(30m).
4. **정상·코스 이름** — 정상은 PEAK 중 이름이 정상·산 이름·괄호 속 봉우리인 것 우선, 공식 높이에 가장 가까운 것. 코스 이름(`nameCourse`) = 들머리(ENTRY·TRANS·PARK·SHELTER·CULTURAL·VILLAGE 300m) → 정상(최고점 300m 안 PEAK, API 에만 있는 이름은 100m 불리) → 끝. 못 만들면 "코스 n"(94 → 45). 높이·날짜·한자 괄호·정상석·대시 자모 정리(`cleanPlaceName`), 깨진 이름 버림.
5. **이정표 안내**(`guideSignposts`) — 방향 코드는 조사자가 걸어온 방향 기준이라 화살표를 빼고 코스마다 `HikingCoursePoi.guide` 에 `way: next(가는 길) | prev(온 길) | null` 을 저장. 이름(앞쪽/뒤쪽 지점·정상) 먼저, 그 GPX 의 이정표면 방향 코드로 보충.
6. **시군구**(3차, [hiking-area.ts](../../apps/friendly/src/modules/hiking/hiking-area.ts)) — 시작·끝·최고점 + 500m 마다 점을 찍어 걸리는 시군구 키(`"51:춘천시"`) 전부. 통계청 2018 시도 코드 → 현행(강원 51·전북 52·전남광주 12), 도의 구 → 시, 군위군 → 대구, 세종시 → 세종특별자치시.
7. **전국 주요 봉우리**(5차 `appendPeaks`) — 정상이 100대 명산 코스 범위(+200m, `PEAK_JOIN_PAD_DEG`) 안 + 그 산 코스 선 1km 안이면 **그 산에 합침**(코스는 80% 넘게 20m 안 겹치면 버림, 봉우리는 그 산의 `peak:<코드>` 지점), 단 **이름 끝이 '산'이고 그 산 이름을 담지 않으면 따로**(`isSeparateMountainName` — 인왕산·우면산·사패산·간월산, 61곳). 나머지는 따로 산(`kind = peak`, id = 봉우리 코드 10자리). 코스 번호는 합친 봉우리 100~(`MERGED_NO_BASE`)·망 1000~(`NETWORK_NO_BASE`). 1km 안 되는 봉우리 코스는 버린다(612, `PEAK_MIN_COURSE_M`).
8. **등산로 망 → 코스**(6차, [hiking-network.ts](../../apps/friendly/src/modules/hiking/hiking-network.ts) `coursesFromNetwork`) — 조각 끝이 다른 조각에 15m 안으로 닿는 곳에서 잘라 그래프로. 정상 = 망에서 가장 높은 점(다른 봉우리 정상 200m 안은 뺌 — 수락산 망의 최고점이 옆 도솔봉). 들머리 = 끝이 막힌 마디 중 정상까지 500m↑·50m↑ 낮은 곳, 낮은 곳부터 최대 4개 → 가장 짧은 길로 왕복(80% 겹치면 건너뜀), 덜 겹치는(30% 안) 두 길이면 넘어가기/한 바퀴 하나. 세 갈래 이상 마디는 갈림길 지점(`jct:`). 원천 `network` — 화면 "이어 만든 길".
9. **지나는·이어진 봉우리, 들머리 이름, 산정보**(5차) — 모든 코스에 선 30m 안 봉우리 지점, 산마다 이어진 봉우리(정상이 서로의 코스 선 30m 안, 최대 8 — 자동으로 산을 묶지는 않는다). 봉우리 코스 들머리 이름은 국립공원 탐방지원센터(9차) → 역·정류장·공영 주차장(노상 뺌) 300m → 브이월드 역지오코딩 리·동(`reverseGeocodeVillage`, 차례로). 산정보는 이름 + 괄호 지역·코스 시군구로 맞추고(`matchPeakInfo`·`pickMountainInfo`) 높이 0 은 빈 값, 봉우리 사진은 한 번에 400곳씩 1장.
10. **국립공원 공식 코스**(9차 `appendParkCourses`, [hiking-park.adapter.ts](../../apps/friendly/src/modules/hiking/hiking-park.adapter.ts)) — EPSG:3857 WKT 를 풀고(`parseWktLines`), 기존 코스와 **같은 길**(서로 80% 넘게 20m 안)이면 그 GPX 코스에 공식 문구 JSON(`HikingCourse.park`)을 붙이고 이름을 공식 코스명으로(지점·고도·노면 유지). 아니면 **새 코스**(`source park`, id `<산 id>-<3000 + 공원 안 순번>`). **방향**(`orientBySections`)은 구간 처음·끝 이름을 센터·등산 지점 이름에 맞춰 정하고(원천 선 절반가량이 거꾸로), 끝 구간이 봉우리(…봉·산·대)인데 100m 넘게 내려가면 다시 뒤집는다(`buildCourse({ keepDirection })`). 작업 트리: 처음·끝 이름이 꼬리(탐방지원센터·공원지킴터·주차장·구간 — `PARK_SECTION_TAIL`, 원문 오타 '세터' 포함)를 떼고 같으면 왕복 문구라 방향을 정하지 않는다(99 → 94). **고도**(`sampleElevations`) — 선을 10m 간격으로 나눠 30m 안 GPX 점에서 빌리고(`nearbyEle`, 70% 이상 덮이고 1km 넘게 비지 않을 때), 작업 트리부터 모자라면 **지형 고도**(`input.demAt`)로 같은 기준을 다시, 그래도 없으면 고도 없음. 문구 JSON 에 `elevationFrom: nearby | terrain`. **같은 길인데 공식 구간 순서가 코스와 반대**면 `reversed: true`(작업 트리, 리포트 `park.opposite`). **산 정하기** — 같은 길 코스의 산 → 선이 가장 많이 겹치는 산(30%↑) → 선 1km 안 정상 → 공원 이름의 100대 명산(15km) → 못 찾으면 뺀다.
11. **경계**(`appendParkAreas`) — 링을 30m 단순화한 encoded polyline JSON(`HikingPark.polygons`), 정상이 공원 안인 산에 `parkId`(정상은 밖인데 공식 코스가 붙은 산은 그 코스의 공원). 이름은 영문 WDPA → `PARK_NAME_KO`.
12. **코스 근처 시설**(7차·9차 `appendFacilities`, `FACILITY_RULES`) — 공중화장실(선 50m, 최대 4, `toilet:`) · 공영 주차장(들머리·날머리 150m, 최대 2, 노상 뺌, `lot:`) · 대피소(선 50m, 최대 4) · 탐방지원센터·안내소(들머리·날머리 300m, 최대 2, `knps:<관리번호>`, 설명 = 연락처). 같은 종류가 이미 50m 안에 붙어 있으면 건너뜀.
13. **쓰기**(`replaceHiking`) — 한 트랜잭션(타임아웃 300초)에서 5표를 비우고 300행 청크로 넣은 뒤 `HikingSync` 에 건수·리포트 JSON.

### 읽기·계산

- **조회**([hiking.service.ts](../../apps/friendly/src/modules/hiking/hiking.service.ts)) — 적재본 읽기만, JSON 열(pieces·profile·surfaces·signposts·guide·images·park)을 계약 모양으로. **예상 시간·난이도는 저장된 이동 분·누적 상승·가파름으로 매번 계산**(`courseEffort` → `@repo/utils`) — 보정값을 바꿔도 다시 적재하지 않는다([raw-store-calibrate-on-read](../concepts/raw-store-calibrate-on-read.md)). 산 상세는 국립공원 공식 코스(공원 안 순번 `seq`)를 먼저, 그다음 `no`.
- **계산 규칙**([hiking.ts](../../packages/utils/src/hiking.ts), [hikingConditions.ts](../../packages/utils/src/hikingConditions.ts), [solar.ts](../../packages/utils/src/solar.ts), PLAN §계산 규칙):
  - **이동 분** — Tobler(1993) v = 6·e^(−3.5·|경사+0.05|) km/h, 경사는 ±0.5 에서 자름(`TOBLER_GRADE_CAP`).
  - **예상 시간** `estimateHikingMinutes` — 2차: `1.12 × 이동 × (1 + min(이동, 360)/600)`(8구간 중앙 오차 2.1%·최대 +37%) → **작업 트리(9차 보강): `1.35 × 이동 × (1 + min(이동, 180)/1500)`**(국립공원 공식 소요시간 103코스 + 2차 7구간, 중앙 절대 11.8%·치우침 +0.1%, 이동 시간대마다 ±5% 안). 짧은 휴식은 포함, 점심·긴 휴식은 없음. summit 은 왕복(`roundTripMin` = 이동 합으로 보정).
  - **난이도** `hikingDifficulty`(나들이 시간 = 왕복 또는 코스 방향 편도) — 어려움: 5시간 30분↑ · 누적 상승 1,000m↑ · 가장 가파른 500m 55%↑ 중 하나. 쉬움: 3시간 미만 · 500m 미만 · 35% 미만이고 밧줄·릿지·사다리 없음. 그 밖 보통. 까닭(넘은 기준)은 `hikingDifficultyReasons`.
  - **가파른 구간** `hikingSteepSections` — 고도 프로필 100m 경사 30% 넘는 곳(7차).
  - **하산 마감** `hikingDaylight` — 늦어도 출발 = 일몰(들머리, NOAA 계산 — 서울 하지·동지 천문연과 1분 안) − 예상 시간 − 30분. 일몰 30분 전보다 이르면 ok, 일몰 전이면 tight, 넘으면 dark.
  - **가장 높은 곳 기온** `estimateTopTemp` — 들머리 격자 기온 − 0.6°C × (코스 최고 고도 − 들머리 고도)/100("추정"), 체감은 기상청 겨울철 식(10°C 이하·1.3m/s 이상, `windChillC`).
  - **주의할 점** `hikingCautions` — 해 진 뒤·일몰 직전 하산, 비·눈 또는 강수확률 60%, 바람 9m/s, 정상 체감 −10°C·영하·30°C, 산불 높음 이상(다소높음은 안내), 미세먼지·초미세먼지 나쁨(`HIKING_CAUTION_RULE` — 우리가 정한 값).
  - **산불 등급** `hikingFireLevel` — 경계값을 확인하지 못해 등급별 면적(d1~d4) 중 면적이 있는 가장 높은 등급과 비율을 그대로("다소높음 23%").
- **산행 조건**([hiking-conditions.service.ts](../../apps/friendly/src/modules/hiking/hiking-conditions.service.ts)) — 3일치 원자료만 주고 날짜·출발 시각 접기는 클라이언트(`summarizeHikingWeather`·`hikingFireInWindow`). 날씨·대기는 앱 싱글톤(`app.weather`·`app.airQuality` — 3차에 대기를 [plugins/air-quality.ts](../../apps/friendly/src/plugins/air-quality.ts) 로 옮김), 산불은 라우트 안 하나의 [ForestFireService](../../apps/friendly/src/modules/hiking/forest-fire.service.ts)(전국 1콜 ≈7,800행·1.7MB 를 3시간 캐시, 하루 쿼터 48, 실패 쿨다운·24시간 stale, 진행 중 합류 — `lib/upstream-guard`). 항목마다 6초(`SECTION_BUDGET_MS`), 늦은 호출은 끊지 않고 캐시를 채운다. 대기는 30km 안 측정소 + 코스 시군구의 예보 권역(`airRegionOf` — 경기 남북·강원 영동영서는 추정 목록, 여럿이면 나쁜 쪽).
- **추천**([hiking-recommend.service.ts](../../apps/friendly/src/modules/hiking/hiking-recommend.service.ts), [hikingRecommend.ts](../../packages/utils/src/hikingRecommend.ts)) — 색인(산·코스·들머리 접근 — 등산 지점 주차·교통 1km → 주차장 1km·버스 500m·지하철 1.5km, 0.01° 격자)을 적재 이력 id 가 같은 동안 6시간 들고, 전 코스를 조건 없이 점수 → 산마다 가장 나은 코스 → 상위 `max(12, limit)` 산만 산행 조건을 받아 재점수(`RECOMMEND_CHECK_TOP`). 점수(약 100점): 산행 시간 25 · 거리 25(차로 30분 만점 → 4시간 0, 위치 없으면 12.5) · 난이도 15(한 단계 차 6) · 해 지기 전 하산 15(빠듯 6·해 진 뒤 −20) · 접근 10 · 오늘의 조건 10(경고 −6·안내 −2, 바닥 −20) · 계절 +5 · 100대 명산 +4(8차). 대략 차로 시간 = 직선 × 1.3 ÷ (40→80km/h) + 10분. 해 시각은 0.1° 칸마다 한 번.

**원천 실측 함정**
- **번호 체계** — GPX `sym`(1~22,989)과 API `poiId` 는 별개(같은 산 같은 번호 259쌍이 전부 30m 넘게 떨어짐). 처음엔 같다고 봤다가 1차 적재에서 정정 → 접두 id.
- zip local 헤더 이름은 깨져 있고 central 이름이 UTF-8 플래그(607/607) — `unzip` 은 경고만, 로더는 central 이름을 쓴다.
- 명산등산로: 방장산만 `mntncd` 빈 값, GPX 폴더명과 이름 다른 산 4(덕숭산(수덕산)·덕유산(향적봉)·도봉산(자운봉)·화악산(중봉)), 교통·관광 문구는 전화번호까지 오래돼 내보이지 않음. 산정보는 동명산(`searchWrd=가리산` 이면 포천이 먼저), 높이 0 = 빈 값(1,326산), 사진 5장은 서버에 파일이 없어 HTML.
- 브이월드 `INCORRECT_KEY` 의 원인은 Referer — 2D데이터·WMS 는 Referer 필요(서버 호출 `Referer: https://ninelife.kr/`), 역지오코딩은 없이 된다. 역지오코딩을 동시 4개로 보내면 수백 건 만에 502·fetch failed → 차례로(개당 40ms 안팎). WMS 는 EPSG:3857 요청이 자주 502 라 `EPSG:900913`.
- 산불위험예보: `excludeForecast=0` 이어야 예보가 옴(생략하면 현재 분석 230행), 시도·시군구를 비우면 전국 229곳, 울릉군은 묵은 행(3시간 넘게 지난 칸은 버림), 시도 코드 현행(전남광주 12), 인천은 2026-07 개편 이름.
- safetydata: **신청 이름과 내용이 엇갈린다** — "국립공원 경계" 키 = 탐방로 코스 `DSSP-IF-00143`, "등산로라인" 키 = 경계 `DSSP-IF-00145`. 키가 데이터별이라 남의 API 에 쓰면 `resultCode 20`, 공인 IP 묶임. 설명의 "탐방로 안전지수 5등급" 열은 없다. 공식 거리와 선 길이 30% 넘게 다른 것 20, 원천 선 절반가량이 구간 순서와 거꾸로, 원문 오타 "백무동탐방지원세터", 소청대피소 `USE_YN 0`, 연락처 "000-000-0000"(백운대탐방지원센터)은 비움, 분소 52곳은 뺀다, 시설 SN 은 겹쳐 관리번호(MNG_NO)가 id.
- 건강효과 POI(15108066, 사용자가 10-25 신청)는 번호 체계가 다르고 난이도 96%가 `001` 이라 못 쓴다. 등산로정보_GW(15158970)는 개발 단계 심의승인 대기.
