# meal — 개인 식단 기록·인식·추천·휴대성

**2026-10-24~10-29 변경 흡수 (31차) — 앱 식단 화면을 네 커밋에 걸쳐 다시 짰다(`1c3e7bc7`·`699761a1`·`6ae0a4c5`·`39276581`, 모두 2026-10-25): 탭 6 → 3(기록·분석·추천) + 설정 화면, 기록 목록의 하루 열량, 상세 액션 정리, 입력 시간 시트와 네이티브 피커, 햅틱. 서버·계약·shared 훅은 그대로이고 웹 식단도 그대로다**: 검토 의견("앱 식단이 웹 폼을 옮긴 인상")을 단계로 나눠 반영했다. 1단계는 바탕·카드·글자 체계·아이콘·필터 접기·날짜 표기, 2단계는 정보 구조, 3단계는 재빌드가 필요한 네이티브 의존성이다. 컴포넌트·토큰(shared `bgGrouped`, `mealTokens.ts`·`mealUi.tsx`) 세부는 [mobile](mobile.md)에 있고, 여기는 도메인에서 바뀐 것만 적는다. (1) **정보 구조**(`699761a1`). 402pt 폭에 탭 여섯(기록·달력·통계·추천·영양·설정)이 꽉 찼고, 성격이 다른 '보기'와 '설정'이 한 층에 있었다. 이제 [app/meal/index.tsx](../../apps/mobile/app/meal/index.tsx) 는 **기록·분석·추천** 셋이다. 달력은 기록 탭의 보기 전환(헤더 달력/목록 아이콘)이다. 통계와 영양은 '분석' 한 화면의 섹션이다([MealAnalysisView](../../apps/mobile/src/components/meal/MealAnalysisView.tsx) — 한눈에 → 주간 인사이트 → 영양소 점검 → 분포·자주 먹은 음식·추천 반응 → 영양제 조언, 영양 쪽은 [meal-nutrition](meal-nutrition.md)). 설정은 헤더 톱니로 여는 별도 화면 [app/meal/settings.tsx](../../apps/mobile/app/meal/settings.tsx) 다. 옛 `?tab=` 값도 새 자리로 연다(`initialFromParam`): `stats`·`nutrition`(·`analysis`) → 분석, `calendar` → 기록 탭의 달력 보기, `preference`(·`settings`) → 기록 탭을 연 뒤 로그인 상태면 설정 화면을 한 번 push. 식사 알림의 `/meal?tab=recommend&slot=`([mealReminders.ts](../../apps/mobile/src/lib/mealReminders.ts) `href`, 루트 알림 허용 목록 [_layout.tsx](../../apps/mobile/app/_layout.tsx))는 그대로 추천 탭·끼니로 연다. **웹은 바뀌지 않았다** — [MealPage](../../apps/web/src/routes/meal/MealPage.tsx) 는 여전히 6탭(`?tab=list|calendar|stats|recommend|nutrition|preference`)이라, 두 플랫폼의 식단 정보 구조가 이번에 갈라졌다(Gotchas). (2) **기록 목록의 하루 열량**(`6ae0a4c5`). 목록이 `FlatList` → `SectionList` 로 바뀌어 날짜 머리글이 위에 고정되고, 오른쪽에 '3끼 · 2,148kcal' 가 붙는다. 합계는 클라이언트가 계산한다. 목록 카드가 열량을 보이는 기록(`mealNutritionLabel` 이 null 이 아닌 것 — 주식이 있는데 곁들임만 값이 있으면 숨김)만 더한다. 그렇지 않은 끼니가 하나라도 있으면 kcal 뒤에 '+' 를 붙인다. 다음 페이지(30건 단위)에 같은 날 기록이 더 있을 수 있는 마지막 날은 끼니 수에 '+' 를 붙인다. 열량을 보이는 끼니가 하나도 없으면 kcal 자리를 비운다(0 으로 쓰지 않는다 — [unknown-vs-zero](../concepts/unknown-vs-zero.md)). 날짜 머리글은 일주일 안이면 `mealDateLabel`('오늘'·'어제'·'그저께'·'3일 전')을 크게, 그 옆에 utils 신규 `mealDateTitle`([mealSlot.ts](../../packages/utils/src/mealSlot.ts) — '10월 25일 (일)', 올해가 아니면 연도, `1c3e7bc7`)을 작게 쓴다. ISO 날짜를 그대로 보이던 자리(달력 선택일·통계 기간·추천 제목·마지막 먹은 날·입력 시각·사진 정리일)도 이 함수로 바꿨다. 검색·필터 패널이 첫 화면의 약 70% 를 차지하던 것은 필터를 눌러야 펼치게 바꿨다. 접혀 있으면 걸린 조건만 칩(누르면 그 조건만 풂)과 배지 숫자로 보인다. (3) **상세**(`699761a1`). 맨 위에 화면 폭 4:3 큰 사진(옆으로 넘김, 썸네일 먼저·보이는 장만 원본), 그 아래 요약·영양 타일 3칸·음식 목록이 온다. 본문의 큰 버튼 셋(수정·삭제·같은 메뉴로 새 기록)을 걷고, 헤더에 '수정'과 '…' 를 뒀다. '…' 는 '같은 메뉴로 새 기록'·'기록 삭제'를 담는다(iOS `ActionSheetIOS`, 그 밖은 `Alert` 버튼 목록). 삭제는 시트에서 고른 뒤에도 "이 기록과 사진을 삭제할까요?"로 한 번 더 묻는다. 2026-10-04 의 "상세 기본 동작은 수정" 위계를 헤더로 옮긴 것이다. 사진 인식 모델명 자리에는 "사진을 AI 로 인식해 남긴 기록이에요." 한 줄을 둔다. (4) **입력 시각**(`699761a1`·`39276581`). 입력 화면엔 시각 한 줄('12:40' + '오늘 · 10월 25일 (일)')만 두고, 누르면 바텀시트 [MealTimeSheet](../../apps/mobile/src/components/meal/MealTimeSheet.tsx) 가 열린다(예전엔 칩 11개가 늘어서 있었다). 시트에는 날짜 앞뒤·시각·끼니별 보통 시각·±30분·지금이 있다. 끼니별 보통 시각은 기존 `GET /meals/time-presets`(최근 90일 끼니별 중앙값, 표본 3건 미만이면 `MEAL_SLOT_DEFAULT_TIME`)다. 값은 고르는 즉시 draft 에 들어가고, '완료'는 닫기만 한다. 3단계에서 네이티브 피커(`@react-native-community/datetimepicker` 8.4.4)가 들어왔다. iOS 는 시트 안에 날짜 컴팩트 버튼(누르면 달력)과 시각 휠을 두고, Android 는 누르면 시스템 대화상자를 연다. 휠은 멈출 때 바로 반영되고 끼니별 시각·±30분과도 맞물린다. 날짜를 바꾸면 시:분은 그대로다. 피커 네이티브가 없는 빌드와 Expo Web 은 예전 숫자 직접 입력('1240')이다. 이것은 2026-08-23 의 "네이티브 시간 피커는 재빌드가 필요해 보류"([PLAN-meal](../../docs/PLAN-meal.md) 진행 기록)의 번복이다. (5) **추천 탭**(`6ae0a4c5`). 추천받기·다시 추천을 같은 크기 버튼으로 맞추고, 서버 안내(`notice`)와 알레르기 주의를 한 띠로 합쳤다. 후보는 테두리 상자 대신 구분선으로 나눈다. '이 메뉴 선택'을 누르면 `candidate_picked` 이벤트를 보내고, 성공하면 화면이 들고 있는 추천의 `feedback.pickedName` 을 그 이름으로 바꾼다. 그러면 버튼이 '선택했어요'(테두리 버튼, 스크린리더 `selected`)로 보인다. 👍👎 이모지 칩은 엄지 아이콘 + 스크린리더 이름("… 추천 좋아요"·"… 추천 별로예요")으로 바뀌었다. 이벤트 종류와 `platform: 'mobile'` 은 그대로다. (6) **햅틱**(`39276581`, `expo-haptics` ~15.0.8, [haptics.ts](../../apps/mobile/src/lib/haptics.ts)). 고르기(칩·스테퍼·아이콘 버튼·달력 날짜·탭/보기 전환), 가벼운 누름(주 버튼·FAB), 완료(기록·설정 저장 성공) 세 가지다. 두 네이티브 모듈 모두 재빌드 전 앱(JS 만 받은 개발 빌드)에서도 죽지 않게 감쌌다. 햅틱은 호출 실패를 무시한다. 피커는 [nativeDateTimePicker.ts](../../apps/mobile/src/lib/nativeDateTimePicker.ts) `loadDateTimePicker` 가 iOS `UIManager.hasViewManagerConfig('RNDateTimePicker')`·Android `TurboModuleRegistry.get('RNCDatePicker'/'RNCTimePicker')` 로 네이티브를 먼저 본 뒤에만 `require` 한다(최상위 import 는 Android 에서 `getEnforcing` 으로 로드가 터진다). 2026-08-23 `expo-document-picker` 지연 로드와 같은 결이다([rn-runtime-gaps](../concepts/rn-runtime-gaps.md)). [docs/mobile-ios-build.md](../../docs/mobile-ios-build.md) 에 "재빌드 전 앱은 햅틱이 빠지고 시간 시트가 숫자 입력" 한 줄이 붙었다. (7) **설정 화면**(`699761a1`). 중요도 0~5 버튼 6개 × 7줄(주황 블록 42개)을 − 숫자 + 스테퍼와 5칸 막대로 바꿨다. 저장 버튼은 '추천 설정 저장'으로 추천 설정 바로 아래에 둔다(식사 알림·내 데이터 카드는 각자 버튼이 있다). 성별·출생연도 안내의 '영양 탭' 은 '분석 탭의 영양소 점검'이 됐다. **1인분 결정 순서(2026-10-02, `mealServingNutrition`)** — ① 메뉴 어휘 portion 에 음식명 지정이 있으면 그 중량 ② 카탈로그 1인분 중량이 100g 초과면 그대로(`direct`) ③ **주식(`isMain`)이면** 종류별 통상 1인분 × 100g당(`typical_portion`) ④ 반찬이거나 통상 중량을 모르면 카탈로그 그대로. 빌려온 영양(`donor_estimate`)은 중량 근거가 없어 손대지 않고, 단백질·나트륨은 카탈로그 1인분 중량이 있을 때만 100g당을 역산한다. 같은 규칙이 저장(`MealService`)·백필([backfill-meal-nutrition.ts](../../apps/friendly/scripts/backfill-meal-nutrition.ts))·추천 후보 건강 판정(`isMain: true` 고정)에 쓰인다 — 그래서 사용자가 고르는 **주식/반찬 구분이 kcal 을 바꾼다**(빠른 추가 기본 목록이 전부 반찬인 이유). → 2026-10-23: ③은 "주식**이거나 원재료 행**이면"으로 넓어졌다 — 원재료(`mfds-raw`)는 주식·반찬 구분 없이 식품군 1회 분량(과일 100·채소 70·버섯 30·감자 140·곡류 90·견과 10·콩 20·달걀 60g, 생고기·수산물 150g, 해조류는 없음)이다. ⑤ 그래도 `missing` 이면 이름 추정(캐시만, 없으면 저장 뒤 백그라운드). `backfill:meal-nutrition --estimate` 는 카탈로그 재계산 뒤 남은 `missing` 이름을 같은 추정기로 묻고(`--dry-run` 이면 묻지 않고 캐시로 채울 수 있는 것만 출력) `fillMissingItems` 로 채운다.

portable backup은 `format='niney-life-pickr.meal-backup'`, `version=1` JSON이다. 연결 사진 JPEG를 canonical base64로 넣고 byteSize·SHA-256·모든 참조를 strict 검증한다. 최대 사진 100개/개별 5MB/합계 50MB/JSON 75MB, 기록 5,000개, 추천 1,000개, 추천당 이벤트 200개다. 복원은 새 id/token을 만들고 기존 preference는 유지한다.
