# 이용허락이 화면·API 모양을 정한다 — 출처표시만(1유형)·원문 그대로(3유형 변경금지)·집계만(제3자 제공 금지)

## Pattern

이 리포의 기능 대부분은 남의 데이터 위에 서 있다(공공데이터포털·AI 허브·국립공원공단·USGS). 그런데 데이터마다 이용허락이 달라서, **같은 "데이터를 보여 준다" 가 세 가지 다른 설계가 됐다.**

| 이용허락 | 설계 결과 | 예 |
|---|---|---|
| 출처표시만(공공누리 1유형, 미국 정부 공개 자료) | 값은 자유롭게 가공·계산, 화면·파일 어딘가에 출처 한 줄 | 날씨·바다 범례·푸터, 집값 SHP, SRTM 지형 고도(푸터·GPX metadata) |
| 출처표시 + **변경금지**(공공누리 3유형) | 원문 문구를 **고치지 않고 그대로** 보이고, 우리 계산은 **옆에 따로** 둔다. 원문이 틀려 보여도(구간 순서가 반대, 오타) 문구는 두고 꼬리표·안내로 알린다 | 국립공원 공식 코스 문구 |
| 원본 제3자 제공 금지(AI 허브) | API 를 두 출구로 — 공개는 식별자 없는 **집계만** + 소셀 억제, 원본은 승인받은 본인 allowlist 만 | 여행로그 |

이용허락은 법무 메모가 아니라 **설계 입력**이다. 3유형이면 "공식 시간을 우리 식으로 보정해 덮어쓴다" 는 선택지가 처음부터 없고, 그래서 계약에 원문 필드와 계산 필드가 나란히 생긴다. 제3자 제공 금지면 공개 스키마에 개별 행 필드가 들어갈 수 없고, 그래서 zod 스키마 자체가 집계 모양이 된다.

## Instances

- **2026-10-26** in [hiking](../topics/hiking.md) (9차 `0e38c4ee` + 작업 트리): 행정안전부 산행안전지도(국립공원공단 원자료)는 공공누리 3유형. 공식 코스의 이름·구간·소요시간·거리·난이도는 원문 그대로 `HikingParkCourse` 에 담고, 우리 예상 시간·난이도는 코스 요약의 다른 필드로 둔다. 웹·앱 공식 칸은 "국립공원공단 안내 문구 그대로입니다(행정안전부 산행안전지도)" 를 붙인다. 같은 길 GPX 코스와 구간 순서가 반대인 3곳도 문구를 뒤집지 않고 `reversed` 로 "반대 방향 기준" 이라고만 알리고, 원문 오타("백무동탐방지원세터")도 그대로 둔다(방향 판정만 꼬리를 떼고 비교). 같은 화면의 지형 고도는 SRTM(공개 자료)이라 계산에 자유롭게 쓰고, 푸터와 GPX metadata 에 "SRTM data courtesy of the U.S. Geological Survey" 를 적는다. GPX 파일 desc 는 원천마다 출처·유형(공공누리 제3유형)을 문장으로 넣는다.
- **2026-09-24** in [api-docs](../topics/api-docs.md) (`1b621c4`): 외부 API 문서의 수기 README 가 이용 조건 절을 따로 둔다 — 여행로그는 집계만·출처 표기, 원본 재구성·재배포 금지, 크롤 데이터 대량 재게시 금지. OpenAPI 자동 생성으로는 뽑을 수 없는 정보라 사람이 적는다.
- **2026-09-13** in [tour](../topics/tour.md) (`99991da`): AI 허브 이용조건(원본 제3자 열람·제공 금지, 집계는 출처 표기로 자유, 국외 반출 금지)이 "한 DB, 두 출구" 구조를 만들었다 — 공개 API 는 식별자 없는 스키마 + 여행자 5명 미만 칸 억제, 원본·사진은 `TOUR_RAW_USER_IDS` allowlist. 공개 화면 운영 노출은 AI 허브 서면 회신 뒤로 걸어 뒀다.
- **2026-08-21~** in [air-quality](../topics/air-quality.md) / [mobile](../topics/mobile.md) / [weather](../topics/weather.md) / [sea](../topics/sea.md): 출처 표기 문자열을 화면마다 따로 써서 **대기 출처의 유형이 웹(3유형)과 앱(1유형)에서 다르다**(미해결 Gotcha). 날씨·바다는 양쪽 다 1유형으로 일치. 이용허락 유형이 상수가 아니라 각 화면의 문자열이라 생긴 어긋남이다.

## What This Means

1. **새 원천을 붙일 때 첫 질문 중 하나는 "이용허락 유형이 무엇인가" 다.** 1유형이면 자유 가공, 3유형이면 원문 필드 + 계산 필드 분리, 제3자 제공 금지면 집계 전용 공개 스키마. 이 답에 따라 계약 모양이 달라지므로 구현 전에 정한다(등산은 9차 검토 의견에서, 여행로그는 PLAN 이용조건 절에서 먼저 정했다).
2. **"고치지 않는다" 는 데이터 정제 습관과 부딪힌다.** 이 리포는 원천 이상치를 적극적으로 고친다(주차 요금 이상치, KOTSA 대표 좌표). 3유형 문구에서는 그 습관을 멈추고 **꼬리표·안내로 알리는 쪽**을 택했다([provenance-tagged-fill](provenance-tagged-fill.md)). 정제는 우리 계산 필드에서만.
3. **출처 문자열은 화면이 아니라 한 곳에 둔다.** 대기 유형 불일치처럼 웹·앱이 각자 문자열을 들고 있으면 어긋난다. 원천 목록(`docs/data-sources.md`)과 코드 상수(`@repo/utils` 또는 계약 주석)를 정본으로 두고 화면이 가져다 쓰는 편이 안전하다.
