## 0. 준비 — 앱 의존성 설치

- **증상**: Metro(`http://localhost:8081`)의 번들 요청이 HTTP 500 `UnableToResolveError: Unable to resolve module expo-haptics
  from apps/mobile/src/lib/haptics.ts` — 식단 화면만이 아니라 앱 전체가 뜨지 않는다. `pnpm typecheck` 의 mobile 도 같은 원인으로
  실패한다(`MealTimeSheet.tsx`·`haptics.ts`·`nativeDateTimePicker.ts`).
- **원인**: 39276581(2026-10-25, Mac 에서 커밋)이 `expo-haptics ~15.0.8`·`@react-native-community/datetimepicker 8.4.4` 를 더했는데
  그 PC 에서 `pnpm install` 을 하지 않았다(`pnpm-lock.yaml` 에는 들어 있다).
- **할 일**
  1. 개발 서버를 끈다 — 적어도 Metro(8081). 설치가 `node_modules` 의 파일을 바꾸므로 API(3000)·웹(5173)도 끄는 편이 안전하다
     (Windows 는 실행 중인 프로세스가 잡은 파일에서 EPERM).
  2. 저장소 루트에서 `pnpm install --frozen-lockfile`.
  3. `pnpm dev` 로 다시 띄우고 `curl http://localhost:8081/status` → `packager-status:running`, 브라우저 `http://localhost:8081` 이
     "Life Pickr" 화면을 그리는지 본다.
  4. `pnpm typecheck` 가 mobile 까지 통과하는지 본다.
- **기기(개발 빌드)**: 두 모듈은 네이티브라 개발 빌드(dev client)를 다시 만들어야 기기에서 동작한다(새 JS 만 받은 옛 빌드도 죽지는
  않게 해 두었다 — 39276581 본문). iOS 는 `pod install` 뒤 [mobile-ios-build.md](mobile-ios-build.md) 대로 prebuilt RN 을 Debug 로
  맞춘다. **Android 는 39276581 이후 어디서도 실행 확인을 못 했다**(날짜·시각 피커 대화상자·햅틱).
- **서버 쪽 전제**: API 가 2026-11-08 코드로 떠 있어야 하고(DB 에 `20261108090000_meal_recommendation_sides` 적용), 운영에서 볼 때는
  배포 뒤 [deploy-friendly.md](deploy-friendly.md)의 영양 단계까지 끝나 있어야 한다.
- **Mac 은 해당 없음(2026-11-08)**: 두 모듈이 루트 `node_modules` 에 있고 `ios/Podfile.lock` 에도 들어 있어 mobile 타입체크가 통과한다.
  iOS 26.5 시뮬레이터(DA0A808C)의 개발 빌드도 두 모듈을 담고 있다(10/25). 위 할 일은 Windows PC 에서만.

  분류만·키마다 요청)을 웹 휴대폰과 같은 시트로 바꿨다. 서버·계약은 그대로(`servingKcal`·`myCount`·`frequent?q=`·`kcal` 를 이제 쓴다).
  - **공유**: 넣을 항목 만들기·줄 바꾸기(인식 계보 `recognitionDishId` 는 남김)·내 기록과 음식 목록 겹침 정리·최근 끼니 같은 차림 한 번만·
    보조 문구·검색어 다듬기(200ms 기다림, 끝 낱자모 떼기, 서버 한도 40자)는 `packages/shared/src/meal/foodSearch.ts`(테스트 12건 — 앱엔

  - **앱 시트** `src/components/meal/MealFoodSheet.tsx`: 식당 고르기처럼 RN `Modal`(formSheet, iOS 는 끌어서 닫기 `allowSwipeDismissal`).

    `keyboardDismissMode="on-drag"`·iOS `automaticallyAdjustKeyboardInsets`. 키보드 완료 키는 '그대로 넣기'이고 키보드는 내리지 않는다

    인분 직접 입력칸은 뺐다(값이 있으면 'n인분' 표시만, 양 칩을 누르면 지운다). 주식/반찬은 '주식'·'반찬·곁들임' 두 칩, 양 칩과 함께

## 4. 확인 기록 (2026-11-08, Mac)

- **데이터**: 이 Mac 의 `prod.db` 는 영양소(`nutrientsPer100gJson`)가 0행이고 식단 기록도 8월 2건뿐이라, 그대로는 영양소 점검이 빈다.
  사용자 DB 를 건드리지 않게 사본(`cp -c`)에 식약처 CSV 를 `load:food-catalog --source=nutrition --refresh-nutrients
  --backfill-nutrition`·`--source=raw` 로 싣고 `link:food-nutrients`(규칙만)를 돌렸다. K-FIND·식품성분표 엑셀이 없어 마그네슘·아연·엽산은
  '판단 보류'. niney@life.com 에 최근 14일 28끼(과일·유제품 거의 없음, 아침 자주 거름)를 API 로 넣었다 → 11일·하루 1,208kcal(64%).
- **띄운 것**: 검증용 API(`.tmp/saju-native/api-server.mts`, :3100, 크론 없음, 사본 DB) + 내 Metro 8082(`EXPO_PUBLIC_API_URL=http://localhost:3100`).

  영양제 조언 2번(kimi-k3), 메뉴 칼로리 판정(맛집 3곳)에 썼다.
