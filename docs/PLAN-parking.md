# 주차(/parking) — 주차장·전기차 충전소·공항 주차

사이드바 **주차** 메뉴(대중교통 다음). 지도 + 패널(바다·집값과 같은 골격), 상단 탭 **주차장 | 충전소 | 공항**.
식당 상세 **가는 법** 탭에 주차 섹션 + 홈 탭 한 줄 요약. 실시간 값은 5분마다 받아 요일·시간 칸에 누적(혼잡 이력).
웹 먼저, 앱(apps/mobile)은 다음 단계. 조사 근거·후보 ID 는 메모리 `project_parking_data_survey`.

## 호출량(개발계정 기준, 서버 1대)

- 주차 실시간 폴러 5분: 서울 1 + 공항공사 1 + 인천 1 = 하루 각 288콜.
- 충전기 상태 폴러 10분(period=10, 9,999행 × 2페이지): 하루 ~288콜. 전량 적재 53콜은 스크립트(수동/배포).
- 로컬 dev 서버도 같은 키로 폴링하므로 두 대가 돌면 두 배 — 인천·충전기 1,000/일 안.
- 끄기: `PARKING_LIVE_CRON=`·`EV_STATUS_CRON=` 빈 값.

## 구조

- DB: `ParkingLot`(원천 접두 id `std:`/`seoul:`/`kotsa:`, 전량 교체) · `ParkingOccupancyStat`(key×요일×시 누적, 상한 = 키 수×168)
  · `EvStation`/`EvCharger`(전량 교체 + 상태 폴러 갱신) · `ParkingSync`(적재 이력).
- 중복: 표준데이터의 서울 행이 서울 원천과 겹치면(100m 안 + 이름 유사도) 서울 행을 남긴다. KOTSA 공영은 서울·표준과 같은 기준에 더해 정규화 이름이 정확히 같으면 300m 안까지 같은 곳으로 보고 뺀다.
- 조회: 일상지도와 같은 점/격자 셀(bbox·줌 임계) + LRU. 실시간은 메모리(폴러가 채움)를 응답에 합친다.
- 적재: `load:parking-lots [--sources=std,seoul,kotsa] [--offline] [--kotsa-dump|--kotsa-json=<폴더>]` · `load:ev-chargers`. 상태 확인 `status:parking`.

## 차수

1. 계약·유틸·DB·주차장 적재(서울+표준) + 실시간 폴러·이력 + 공항 + 라우트·테스트
2. 전기차 충전소(적재·상태 폴러·라우트·테스트)
3. 웹 `/parking` 3탭 + NAV
4. 식당 가는 법 주차 섹션 + 홈 요약(리뷰 '주차' 관점·팁 집계 라우트)
5. docs/api 재생성 · deploy.sh · 메모리/위키

## KOTSA — 한국교통안전공단 주차정보(15099883)

**결정(2026-10-05 사용자, 권장안)**: 공영 + 실시간 연결 민영을 넣고 서울 실시간은 서울 API 유지 → 실측 뒤 **공영 정적 정보만**
(실시간은 쓸 수 없어 뺐다 — 아래). 넣는 것: 공영 + 요금 구분(무료/유료) 있는 행, 운영정보(요금·운영시간), 서울·표준데이터와
겹치는 곳은 빼고 새 곳만(정적 정보는 기존 원천 우선).

**실측(2026-10-05)**
- 건수: 시설 = 운영 = 1,767,934 · 실시간 787,238. 페이지당 1만 행까지. 응답은 감싸개 없이 `{ resultCode:'0', totalCount, <오퍼레이션 이름>:[…] }`.
- 지역 필터는 **옛 행정코드만**(강원 42·전북 45·부천 41190·화성 41590·군위 47720 — 새 코드 51·52·41192 는 0건). 로컬 DB 의
  새 코드를 옛 코드로 바꾼 후보를 totalCount 로 대조해 251곳 확정 → `modules/parking/kotsa-sigungu.ts`.
- **원천 결함**: 행정코드가 바뀐 지역(강원·전북·부천·화성·군위·옛 인천 남구 28170, ≈24만 행)은 어느 필터로 불러도 totalCount 만
  오고 목록이 빈다. 전국 목록에서도 빠져, 필터 없는 전국 페이지는 120쪽 뒤부터 빈다(totalCount 와 불일치).
- **초당 한도**가 가이드(30tps)보다 훨씬 낮다 — 동시 4개면 대부분 `LIMITED_NUMBER_OF_SERVICE_REQUESTS_PER_SECOND_EXCEEDS_ERROR`.
  순차 + 350ms 간격(`createCallSpacer`), 초당 한도 오류는 2.5초 쉬고 재시도.
- 시설 구성: 대부분 민영 부설(1~5면 빌라·주택, 이름 빈 행 많음, 요금 구분·운영정보 없음). 공영은 13,645행으로 관리 ID 순(둘째
  구간 111xx·112xx)이라 시군구 목록 앞쪽 — 전부 시군구 첫 페이지 안. 운영 목록도 같은 순서.
- 공영 중 요금 구분이 빈 행 2,981(광주 1,949·경기 740)은 업체·아파트·교회·개인 주택(사람 이름이 든 행도 있음)이 섞여 뺀다.
- **거주자 우선 주차 구획**은 뺀다(94행) — 부산 동구 '수5-5(주거지)'·'초량3동-업무지7구간'(시간 요금 없이 월 4만~6만 원)과
  '○○거주자우선주차장'. 서울 원천의 '거주자 우선 전용' 제외와 같은 취지. '업무지구'(북구 동편업무지구 공영)는 실제 공영이라 남긴다.
  (표준데이터에도 이름에 '거주자'·'주거지'가 든 행이 34곳 있지만 손대지 않았다.)
- **기본요금 이상치**: 정수 최댓값(2,147,483,647)이 80행, 월정액을 잘못 넣은 4만 원 등 — 기본요금(실측 기본 시간은 모두 30분)이
  1만 원을 넘으면 정보 없음. 정리 뒤 최대 4,500원.
- **좌표 정리**(로컬 적재 2026-10-05 수치):
  - 입구 좌표가 없는 행 1,612(≈16%)는 주소로 지오코딩한다(서울 구영과 같은 `geocodeLifeRows` + 영구 캐시).
  - **대표 좌표**: 이름 다른 주차장 여럿이 한 좌표에 몰린 곳(구미 35곳·대구 북구 11곳이 한 점, 3곳 이상 몰린 좌표 63곳·270행)은
    원천 좌표를 버리고 주소로 다시 찾는다. 위 행과 합쳐 1,882행 중 1,721 찾음(91%, VWorld 첫 실행 약 1,700콜 — 이후 캐시).
  - 주소도 뭉뚱그려져(대구 '○○길인근' 노상 등) 지오코딩이 다시 한 점에 3곳 이상 모이면 위치를 모르는 것으로 보고 뺀다(241행).
    위치를 끝내 못 찾은 행 161 도 뺀다(좌표 없이는 기존 주차장과 겹침을 판정할 수 없다). 둘씩 붙은 구획(압구정고가1·2)은 그대로.
  - **KOTSA 끼리 중복**: 같은 주차장이 관리 ID 만 달리 여러 번 실린 행 1,312 — 이름 같고 300m 안이면 원천 좌표 행을 남긴다.
  - **기존과 겹침**: KOTSA 좌표는 입구라 같은 주차장도 기존 원천과 100~300m 어긋난다(종묘·세종로 196m, 방향 일정하지 않음) →
    기존 규칙(25m 안 또는 100m 안 + 이름 유사)에 더해 이름이 정확히 같으면 300m 까지 같은 곳(`KOTSA_SAME_NAME_RADIUS_M`).
  - 결과: KOTSA 8,656곳 중 기존과 같은 곳 6,605 · **새로 더한 곳 2,051**(원천 좌표 1,597 · 주소로 찾음 454) → 전체 20,219곳
    (서울 836 · 표준 17,332 · KOTSA 2,051). 남은 같은 좌표 쌍 36(둘씩 붙은 구획), 3곳 이상 몰린 좌표 0, 이름 같은 행이 300m 안에
    또 있는 곳 0. 화면(웹 데스크톱·모바일)에서 지도 핀·목록·상세(출처·'위치는 주소로 찾은 값')·하단 원천별 수를 확인했다.
- 운영정보(공영 13,074): 기본요금 3,632 · 추가요금 1,874 — 추가 시간만 있고 **추가요금 0원인 행 11,200 은 정보 없음**으로 ·
  1일 2,415 · 월정액 2,771 · 회차 무료 0 · 운영시간 빈값/0 6,201. 평일 요일끼리·일요일과 휴일이 다른 행은 0.
- 그 밖: 가이드 필드명 `prk_chrge_se` ≠ 실제 `parkng_chrge_se`, 같은 관리 ID 여러 행(좌표·구획수 다름), 한 ID 가 수백 행인 쓰레기 ID.
- **실시간을 쓰지 않는 이유**: 시군구로 거르면 시설과 이어지는 실시간은 전국 858행(40곳, 서울 237)뿐인데, 15분 간격 5회(월요일
  07:28~08:28, 1시간) 관측에서 값이 하나도 바뀌지 않았다(같은 시간 서울 API 의 종묘 가용 대수는 1,055→1,029 로 움직였고 KOTSA 는 158 고정 — 가이드의 갱신 주기
  '일 1회'). 값이 바뀌는 행(전국 페이지 1만 행 중 3.5분에 110)은 `00000-19199-…` 처럼 시설에 없는 ID 라 이름·좌표·시군구를 모른다.
  원천이 실시간을 시설 ID 로 이어 주면 재검토.

**적재**: `load:parking-lots` 기본 원천에 `kotsa` — 시군구 251곳마다 시설 첫 페이지(끝 1천 행에 공영이 있으면 다음 페이지) + 운영
정보(공영이 끝나는 위치 + 50행, 빠지면 첫 페이지 전체) ≈ 470콜(실측 4분 20초). 겹침 판정은 격자(칸 한 변 ≥ 판정 거리) 이웃
칸만 보는 `matchParkingDuplicates`(전국끼리도 빠름). 저장본 `--kotsa-dump=<폴더>` / 재적재 `--kotsa-json=<폴더>` / 일부 `--kotsa-codes=…`.
배포는 `deploy.sh` 의 `parking_data` 가 `kotsa=0` 이면 한 번 적재(이후는 9번으로). 지오코딩 결과는 저장소 압축본
(`life-geocode-cache.json.gz`, 2026-10-05 재내보내기 107,161건)으로 운영에 가져가므로(`life_map_data` 가 압축본이 바뀌면 가져온다 —
`parking_data` 보다 먼저) 운영 적재는 VWorld 를 거의 부르지 않는다. 9번만 단독으로 돌리면 압축본을 안 가져와 새 주소는 VWorld 로 찾는다.

**후속 후보**: 운영정보로 표준데이터 행의 빈 요금 보강 · 원천 결함(행정코드 바뀐 지역 목록 누락) 문의 · 실시간 재검토(위 조건).

## 함정

- data.go.kr 키는 Encoding 값 — `toServiceKeyPart`(이중 인코딩 금지).
- 서울 `GetParkInfo` 유무료 코드는 `Y=유료/N=무료`(이름과 반대 느낌), 토·공휴일 무료는 SAT_/LHLDY_ 필드 별도.
- 운영시간 `0000-0000` 은 정보 없음, `2400` 은 자정.
- 공휴일은 판정하지 않는다(일요일만 공휴일 시간으로) — 상세에 표시.
