# 사주 — 나의 오행 지도

2026-09-06. 사용자 결정: **Kimi를 고려하고 나머지는 추천안으로 진행**. 개인 사주·올해의 흐름·오늘의 흐름을 웹에 구현했다. 앱·궁합·대운은 후속 범위다. 코드와 임시 DB 검증을 완료하는 작업이며 운영 배포는 별개다.

## 제공하는 경험

- `/saju`: 로그인 없이 생년월일, 양력/음력·윤달, 정확한 시간/대략의 시간/모름을 입력한다. 이름과 성별은 요구하지 않는다.
- **나의 사주**: 일간의 상징, 네 기둥과 독음, 오행 구성, 성향·일·관계·균형, 작은 실천과 돌아볼 질문.
- **올해의 흐름**: 해당 해의 연주와 일간 관계, 절기로 나눈 12개월의 시작 시각·관계 풀이.
- **오늘의 흐름**: 서울 날짜에 고정한 일진과 일간 관계. 같은 입력·기간·버전·모델의 생성 결과를 캐시한다.
- 명식은 먼저 보여주고 AI 해석을 뒤에 채운다. AI 설정 부재·장애·시간 초과·한도 도달 시 계산 근거의 기본 풀이를 제공한다.
- 짙은 먹색과 옥빛·금빛의 3D 천문대, 기둥 공개, 오행 선택과 상징 강조. 연출 건너뛰기, 작은 화면, 모션 줄이기, WebGL 미지원에 대응한다.
- `/me/saju`: 직접 선택한 결과만 보관한다. 게스트는 브라우저 최근 20개, 회원은 계정에 저장하고 개별 삭제한다.

## Kimi와 AI 해석 v3

기본은 **`OLLAMA_SAJU_MODEL=kimi-k3`**. 기존 Ollama Cloud 키를 상속하며 어드민 AI 설정에서 `saju` 용도로 별도 선택할 수 있다. 모델 목록의 사주 추천도 K3를 우선한다. 사용량 한도는 `saju-reading`으로 관리한다.

최신 v3는 합성 프로필 12개로 Kimi K3를 평가했다. **12/12가 첫 호출에서 출력 검증을 통과**했고 중앙 응답 시간은 **12.574초**, 범위는 8.348~17.885초였다. 일간 미확정·DST 중복 시각 사례를 추가했다.

이전 v2에서 동일한 합성 프로필 10개로 비교한 기록:

| 모델                   | 출력 검증 통과 | 중앙 응답 시간 |         범위 |
| ---------------------- | -------------: | -------------: | -----------: |
| `kimi-k3`              |          10/10 |        10.62초 | 7.51~15.90초 |
| `deepseek-v4-pro:0813` |          10/10 |         6.73초 |  5.33~8.28초 |

Kimi K2.6은 초기 v1 비교에서 8/10, 중앙 42.95초였고 두 건이 60초에 시간 초과했다. K3는 사용자 선호를 반영한 기본 모델, DeepSeek는 속도를 우선할 때 어드민에서 선택할 비교 후보다. 자동으로 다른 모델에 재전송하지 않는다.

초기 결과의 오행 결핍 단정·질문 복사·긴 제목을 검토해 v2 지침을 강화했다. v3에서는 모델에 오행 개수 대신 상징 근거를 전달하고, 요약/본문의 문단 통째 반복·틀린 일간·계산에 없는 한글 간지·기간 근거 없는 올해/오늘 주제를 추가로 거절한다. 12개 본문도 직접 읽어 확인했다. 사소한 어색한 표현과 상징에 기댄 일반화는 남아 있다. **출력 검증 통과가 모든 해석 문장의 타당성이나 미래 예측을 보증하지는 않는다.** [원본 측정과 평가 메모](../apps/friendly/research/saju/README.md)에 버전별 결과를 보존했다.

[Ollama Cloud는 structured outputs를 지원하지 않는다고 안내](https://docs.ollama.com/capabilities/structured-outputs)하므로 서버에서 Zod와 근거를 검사한다. 같은 모델의 형식 재시도는 최대 1회, 전체 대기는 60초다. 모델에는 계산 근거와 선택한 관심사만 전달한다. 원본 생년월일·정확한 시각·계정 정보는 보내지 않는다.

## 저장·공유·일관성

- 기본 조회는 출생정보·결과를 DB에 저장하지 않는다. 성공한 AI 결과만 서버 메모리에 캐시하며 사용자/게스트별로 분리하고 최대 24시간, 개수 제한이 있다. 기본 풀이는 캐시하지 않아 사용자가 즉시 AI 재시도를 할 수 있다. 동시 요청 합류·공통 사용량 한도는 그대로 적용한다.
- 회원 저장은 소유자가 가진 임시 영수증으로만 가능하다. 서버 재시작·영수증 만료 후에는 다시 생성해 저장한다. 기기 보관 결과는 서버 재시작 후에도 출생정보로 공개 명식을 다시 계산해 공유할 수 있다.
- 캐시 키: 입력·계산 버전·기간·프롬프트 버전·모델 + 소유자. 동시 동일 생성은 합류한다. 저장한 AI 결과는 재사용하며 기본 풀이 저장이 이후 AI 재시도를 막지 않는다.
- 회원 저장 시 같은 입력의 캐시·미완료 영수증에도 저장 ID를 연결한다. 결과 삭제 시 연결된 메모리 캐시·영수증과 **해당 저장 결과에 연결해 만든** 공유도 함께 삭제한다. 저장 전 독립적으로 만든 공유는 각각 취소한다.
- 공유 보기 토큰과 취소 자격증명을 분리한다. 취소 자격증명은 공유한 브라우저에 보관하며 공개 URL에 넣지 않는다. 공유 페이지에서 다시 취소할 수 있다. 브라우저 저장소 삭제 후에는 게스트 취소 자격증명이 사라진다.
- 서버는 공유 이미지 캐시를 읽기 전에 공유 행의 존재를 확인한다. 공유 취소 후 PNG와 JSON은 404, OG에도 기존 소개를 남기지 않는다. 이미 내려받은 사본은 회수하지 않는다.
- 공유·회원 보관 화면은 탭 복귀 시 다시 조회한다. 재조회가 실패하면 이전 상세/공유 카드를 숨긴다.
- 게스트 기본 한도: 20회/일, IP 200회/일·10회/분, 전역 1,000회/일, 게스트 전역 예산 90%까지. 회원 정책은 기존 공통 한도 서비스와 동일하다. 어드민에서 변경할 수 있다.

## 코드와 운영 반영

- 계약: `packages/api-contract/src/schemas/saju.ts`, `Routes.Saju`.
- 공유 로직: `packages/shared/src/api/saju.api.ts`, `hooks/useSaju.ts`, `stores/sajuHistoryStore.ts`.
- 서버: `apps/friendly/src/modules/saju/` — 엔진·해석·저장·공유·PNG·OG.
- 웹: `SajuPage`, `SajuHistoryPage`, `SajuSharedPage`, `components/saju/`.
- 스키마: `SajuReading`, `SajuShare`, `20260906090000_add_saju` 마이그레이션.

운영 DB에는 마이그레이션을 적용하지 않았다. 세션의 로컬 `.env`가 `prod.db`를 가리키고 기존 미적용 마이그레이션도 있어, 운영 데이터를 건드리지 않고 신규 SQL을 임시 DB에서 검증했다. 반영 시 대상 DB·기존 마이그레이션 상태를 확인하고 저장소의 정상 배포 절차로 처리한다. K3 설정·기존 Cloud 키 상속을 확인하고, SNS 미리보기에는 [nginx `/saju/s/` 프록시](deploy-friendly.md)를 반영한다.

후속 범위는 앱 UI, 궁합, 대운, 해외 출생·지역 태양시, 여러 프로필 관리다. 대운의 성별 기준·순역·시작 시점은 별도로 검증하기 전 노출하지 않는다.

## 실제 서버 재검증 — 2026-09-06

사용자의 오류 제보 후 실행 환경을 다시 확인했다. 기존 5174 미리보기는 Cloud 키 없는 기본 풀이 모드였으며, 기본 `.env`의 DB에는 사주·사용량 한도 테이블을 포함한 마이그레이션 10개가 미적용 상태였다.

- 기존 DB의 일관된 SQLite 복사본 `.tmp/saju-runtime/local.db`에 미적용 마이그레이션을 모두 적용했다. 원본 `apps/friendly/data/prod.db`와 `.env`는 변경하지 않았다.
- 실제 진입점 `src/server.ts`를 3000번에서 실행하고, Vite 5173의 `/api` 프록시로 연결했다. 접속 주소는 `http://localhost:5173/saju`다. 복사본의 계정·Cloud 설정을 사용하며 자동 크롤링·Telegram·요약 재시작·군집 재계산은 비활성화했다.
- 프롬프트 v2 당시 Playwright의 실제 HTTP 요청 8건(게스트 7건·회원 1건) 모두 `200`, `source: ai`, `model: kimi-k3`를 확인했다. 브라우저 측 응답 시간은 약 8.46~15.88초였다.
