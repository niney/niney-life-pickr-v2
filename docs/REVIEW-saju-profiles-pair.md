# 출생 프로필과 우리의 오행 지도

2026-09-06. 사용자가 다음 구현으로 승인한 출생 프로필 관리와 두 사람의 궁합을 반응형 웹에 추가했다. 개인 사주 계산과 Kimi 설정을 재사용한다.

## 사용 흐름

- `/me/saju/profiles`: 별명·양력/음력·윤달·출생시간·계산 관례를 최대 20명까지 저장하고 수정·삭제한다. 게스트는 현재 브라우저, 회원은 계정에 보관한다. 로그인할 때 게스트 출생정보를 자동 업로드하지 않는다.
- 현재 풀이와 보관함의 출생정보를 프로필로 만들 수 있다. 프로필의 나의 사주·오늘·올해 바로가기는 출생정보 재입력 없이 해당 풀이를 시작한다. URL에는 프로필 ID와 풀이 종류만 넣는다.
- `/saju/pair`: 두 프로필을 고르거나 직접 입력하고 연인·파트너 / 친구 / 가족 / 함께 일하는 사이 중 하나를 선택한다. 관계 계산을 먼저 보여주고 AI 해석을 이어서 표시한다.
- 서로 다른 색의 두 오행 지도, 빛으로 연결된 궤도, 오행별 강조, 세 장의 해석, 함께 나눌 질문과 작은 실천을 제공한다. 모션 줄이기 설정을 존중한다.
- 공유 링크와 1080×1440 PNG에는 두 상징과 확정 오행 구성, 서버가 정한 제목만 담는다. 별명·생년월일·시간·질문·선택한 관계 유형·AI 자유문장은 공개하지 않는다. 공유 취소는 기존 취소 자격증명을 사용한다.

프로필과 풀이 보관은 독립적이다. 프로필 삭제는 이미 별도로 저장한 개인 풀이·독립 공유를 삭제하지 않으며 화면에 안내한다. 이번 궁합 풀이는 자동 저장하지 않고 공개 상징 카드로 공유할 수 있다. 궁합 해석 보관함, 앱 UI, 대운, 해외 출생·지역 태양시는 후속 범위다.

## 계산과 AI의 범위

`calculateSajuPair`는 각자의 기존 명식을 계산한 뒤 **일간 오행의 관계와 서로에 대한 십성**을 구한다. 목→화→토→금→수→목의 상생과 목→토→수→화→금→목의 상극 순서를 사용한다. 근거는 [국사편찬위원회 삼국사기 주석 331](https://db.history.go.kr/item/compareViewer.do?levelId=sg_032_0030_0050)이다. 궁합의 문화적 맥락은 [한국민족문화대백과사전](https://encykorea.aks.ac.kr/Article/E0006817)을 참고했다.

관계 방향은 두 사람의 순서를 바꾸면 함께 바뀐다. 같은 오행은 별도로 구분한다. 어느 쪽이든 출생 시간 범위에서 일간을 확정하지 못하면 오행 관계와 상호 십성 모두 미확정으로 유지한다. 지지 합충·용신·대운을 계산하거나 오행 개수의 합으로 궁합 점수를 만들지 않는다. 전통의 상생·상극을 실제 행복·갈등·우열로 판정하지 않는다.

AI는 기존 `saju` 설정의 `kimi-k3`와 `saju-reading` 한도를 사용한다. 개인 사주와 궁합이 같은 한도를 소비한다. 두 사람의 상징·계산 관계·상호 십성·풀이 범위, 선택한 관계 유형과 질문만 전달한다. 원본 출생정보·별명·계정·오행 개수는 전달하지 않는다. 같은 소유자의 동시 요청은 합류하고 성공한 AI만 24시간/200건 메모리 캐시한다. 입력·모델·계산 버전·궁합 프롬프트 버전을 캐시 키에 포함한다. 최대 두 호출, 전체 60초 제한 후 기본 풀이로 전환하며 바로 재시도할 수 있다.

궁합 프롬프트 v1의 6개 응답을 읽었을 때 일간이 미확정인 사람에게 연주·월주의 기운을 대신 배정하는 문장을 발견했다. v2는 모델의 근거에서 개별 기둥을 제외하고 상징과 확인된 관계에 집중한다. 상징으로 실제 성격·선호·역할을 배정하지 말고 서로의 경험을 묻도록 지침도 보강했다.

v2의 합성 사례 9개는 Kimi 첫 호출에서 모두 출력 검사를 통과했다. 같은 오행·양방향 상생·양방향 상극·미확정 2개와 관계 4종, 질문을 통한 지시문 삽입을 포함한다. 중앙값 10.875초, 범위 8.608~15.167초였다. 개별 기둥으로 미확정 일간을 대체한 문장은 이 표본에서 발견하지 못했다. 상징에 기댄 성향 일반화, 문장 일부의 반복, 사소한 오탈자는 남아 있다. 9/9는 출력 계약 검사 통과율이며 해석의 정확도나 예측력을 뜻하지 않는다. [원본과 평가 기록](../apps/friendly/research/saju/README.md)에 두 버전을 보존했다.

## 데이터와 동시성

새 `SajuProfile` 테이블은 `User` 외래 키와 삭제 연쇄, 별명, 출생 입력 JSON, 수정 버전, 생성/수정 시각을 가진다. API의 모든 프로필 작업은 인증된 소유자로 제한한다. 수정은 `revision`을 확인해 다른 창의 변경을 덮어쓰지 않고 409를 반환한다. 게스트 저장도 수정 버전과 직렬 큐를 사용하며 지원 브라우저에서는 Web Locks로 탭 간 쓰기를 직렬화한다. 저장 실패나 최대 개수 초과를 조용히 무시하거나 오래된 프로필을 밀어내지 않는다.

React Query는 계정별 키를 사용하고 탭 복귀 때 다시 조회한다. 저장소 변경 이벤트도 게스트 목록을 갱신한다. 계정 전환·선택 변경·프로필 수정/삭제 뒤에는 이전 궁합 응답을 버린다. 현재 선택과 다른 공유 창도 숨긴다.

실제 바로가기 검증 중 캐시된 프로필로 진입하면 React StrictMode의 초기 cleanup이 요청을 취소한 채 로딩이 남는 문제를 발견했다. 자동 요청을 취소 가능한 microtask에서 시작하도록 수정했다. 캐시를 미리 채운 StrictMode 테스트에서 수정 전 AI 호출 0건으로 실패하고 수정 후 정확히 1건으로 통과했다.

## 검증

- API·사주 계산·프로필 소유권/수정 충돌·공유 JSON/PNG/취소·AI 설정·한도·타로 회귀: 175개 통과.
- 웹 전체 107개, shared 68개, utils 246개 통과. 프로필 CRUD, 결과에서 프로필 생성, 바로가기, 늦게 도착한 궁합 응답 무효화를 포함한다.
- `20260906140000_add_saju_profiles`를 HEAD 스키마로 만든 빈 임시 DB에 적용하고 `prisma migrate diff --exit-code`로 현재 스키마와 차이가 없음을 확인했다.
- `pnpm typecheck` 6개 작업(앱 포함)과 변경 파일 ESLint를 통과했다. 마지막 UI 수정 후 웹 전체 107개와 API 프로필·궁합 19개를 다시 확인했다.
- `pnpm --filter friendly build`, `pnpm --filter web build`와 `git diff --check`를 통과했다. 기존 `three` 청크의 500kB 초과 안내는 남아 있다. 궁합은 SVG를 사용하며 해당 3D 화면을 실행하지 않는다.

실제 Fastify 3000 + Vite 5173을 Playwright로 실행해 다음 흐름을 확인했다. 합성 계정과 출생정보만 사용했다.

- 게스트 프로필 생성·수정·삭제·새로고침 유지 → 오늘 바로가기의 실제 Kimi 응답 → 현재 결과에서 프로필 생성.
- 두 프로필 선택 → 친구 궁합의 실제 `kimi-k3`/프롬프트 v2 응답 → 3개 해석 표시. 최종 실행에서 생성 시작부터 화면·스크린샷 확인까지 9.656초였다. 직접 모델 probe의 순수 응답 시간과는 측정 범위가 다르다.
- 1440px·390px 결과 화면과 오행 강조, 모션 줄이기, 공유 PNG 다운로드·눈으로 확인. 390px에서 가로 넘침이 없었다. 결과로 자동 이동했을 때 돌아가기 버튼이 공통 상단바에 가리지 않도록 스크롤 여백을 두었다.
- 공개 JSON에 별명·출생정보·질문·AI 본문 없음, OG 생성, 다른 탭에서 공유 취소 후 JSON·PNG·OG 404, 열린 페이지의 visibility 전환 재조회로 취소된 카드 숨김.
- 회원 가입 후 게스트 프로필과 분리 → 계정 프로필 생성·수정·삭제·새로고침 유지. 인증 없는 프로필 조회 401. 페이지 JavaScript 오류 없음.

최종 로컬 기록은 `.tmp/saju-runtime/next-verification.json`, `pair-real-result.json`과 화면 PNG이며 Git에서 제외된다. 탭 복귀는 Query의 실제 `visibilitychange` 구독으로 재조회와 카드 숨김까지 확인했다.

운영 DB와 `.env`는 변경하지 않았다. 실행 중인 로컬 서버는 기존 `.tmp/saju-runtime/local.db` 복사본에 프로필 마이그레이션을 추가 적용했다. 자동 외부 작업은 비활성화된 상태다. 운영 반영에는 이 마이그레이션과 기존 [공유 OG 프록시](deploy-friendly.md) 설정이 필요하다.

## Chrome에서 추가 직접 검수

사용자의 브라우저 직접 확인 요청으로 Chrome의 실제 탭에서 입력과 버튼을 조작했다. 시작 시점의 3000번 서버는 기본 `.env`의 `apps/friendly/data/prod.db`를 사용하고 있었다. 명식 계산은 성공했지만 AI 요청에서 `usage_quota_settings` 테이블 누락 오류를 재현했다. 해당 서버를 중지하고 `bash .tmp/saju-runtime/start-api.sh`로 검증용 복사본에 연결해 재시작했다. 원본 DB와 `.env`는 변경하지 않았다. 이후 같은 화면의 재시도로 개인 사주 AI 해석이 완료되었다.

재시작 후 개인 사주 → 기기 보관 → 결과에서 프로필 생성 → 별명 수정/새로고침 유지 → 시간 모름 프로필 추가 → 오늘 바로가기 → 두 프로필의 친구 궁합을 확인했다. 모바일 390×844에서 본문과 오행 선택이 동작하고 문서 폭도 390px였다. 공유 링크 복사·새 탭 공개 카드·공유 취소·취소된 주소의 재접속 안내까지 확인했으며 최종 탭의 JavaScript 오류 로그는 없었다. 기존 Three.js의 Clock 사용 중단 예정 경고는 남아 있다. 검수 후 화면 크기를 복원하고 궁합 결과 탭을 남겼다.

공유 PNG가 실제 화면에서 1080×1440으로 로드되는 것은 확인했다. 이미지 저장 버튼을 눌렀으나 브라우저 도구의 다운로드 이벤트 대기가 만료되었고, Chrome 다운로드 관리 페이지 접근은 브라우저 보안 정책이 차단했다. 따라서 **이번 직접 검수에서 파일 다운로드 완료는 확인하지 못했다**. 앞 절의 Playwright 다운로드 통과는 이전 실행의 별도 기록이다.

현재 로컬 확인용 API 재실행 명령은 `bash .tmp/saju-runtime/start-api.sh`다. 기본 `.env`를 사용하는 일반 개발 실행은 원본 DB를 선택하므로, 원본 DB의 미적용 마이그레이션을 별도로 처리하기 전에는 같은 누락 오류가 재발할 수 있다.
