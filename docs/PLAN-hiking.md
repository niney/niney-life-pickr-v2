# 등산(/hiking) — 100대 명산 코스·오늘의 조건·추천

사이드바 **등산** 메뉴(독립 페이지). 지도 + 패널(바다·집값·주차와 같은 골격).
100대 명산 607개 코스부터 시작해 코스 상세(선·고도·노면·이정표) → 오늘의 조건(날씨·대기·산불·일몰) → "오늘 어느 산"
추천과 가는 법·주차·맛집 연동까지. 1~9차는 **웹만**, 10차(2026-10-26)에 앱(apps/mobile)은 목록·산·코스 화면까지. 조사 근거는 메모리 `project_hiking_data_survey`.

## 구조 (1차 구현 기준)

### DB (Prisma, 마이그레이션 `20261024234228_add_hiking`)

- `HikingMountain`: id = 산 코드(`mntncd` = 산정보 `mntilistno`), 이름·GPX 폴더명·높이·소재지·시도 키(`regions`)·부제·개관·
  상세·선정 이유·공식 코스 문구(원문)·정상(이름·좌표·고도)·bbox·코스 수·최단/최장 길이·사진 순번 JSON.
- `HikingCourse`: id = `<산 코드>-<GPX 번호>`. 이름(+출처 points/number)·들머리/끝/정상 이름·길이·고도 유무·누적 상승/하강·
  최고/최저 고도·시작/끝 좌표·원점회귀·조각 수·끊김 수와 직선 합·bbox·조각별 encoded polyline(4m 단순화) JSON·고도 프로필
  JSON(20m)·노면 범위 JSON. 2차(`20261025030000_hiking_time_guide`): 형태 `shape`(loop/summit/traverse)·이동 분
  `moveMin`/`moveRevMin`(Tobler, 보정 전)·가장 가파른 500m `steepPct`.
- `HikingPoi`: id = `gpx:<sym>` / `api:<poiId>`, 분류(GPX 원문 코드)·이름·설명·좌표·고도·이정표 JSON·출처(gpx/api/both).
- `HikingCoursePoi`(코스 ↔ 지점, `atM` = 코스 시작에서 거리, 2차 `guide` = 이 코스 기준 이정표 안내 JSON) · `HikingSync`(적재
  이력 + 리포트 JSON). 전량 교체.
- 예상 시간·난이도는 저장된 이동 분·누적 상승·가파름으로 **읽을 때 계산**(`@repo/utils` — 보정값을 바꿔도 다시 적재 안 함).
- 3차(`20261025120000_hiking_sigungu`): 코스 `sigungu` = 코스가 걸친 시군구 키 JSON(`"51:춘천시"`, 산불위험예보·대기 예보 권역용).

### 적재 `pnpm --filter friendly load:hiking [zip] [--no-images|--refresh-images|--dry-run]`

1. zip 을 풀지 않고 읽어(`listZipEntries`+`readZipEntryBuffer`) GPX 를 정규식으로 해석 — `hiking-gpx.ts`(순수 함수).
2. 정리:
   - **고도 튐**: 직전 유효 점 대비 경사 1(45°, 10m 미만은 10m 로 본다)을 넘는 점을 버리고 앞뒤 보간 → 이동 중앙값(창 5).
     결과: 누적 상승 최대 9,707m → 2,011m, p50 698m. 전부 0 인 대암산은 고도 없음.
   - **조각 잇기**: 첫 조각부터 끝점이 가장 가까운 조각을(필요하면 뒤집어) 잇고 30m 안이면 합친다. 남은 끊김 224코스.
   - **방향**: 편도이고 시작이 끝보다 30m 이상 높으면 통째로 뒤집는다(108코스). 원점회귀 100코스는 그대로(시작 지점 돌리기는 2차).
3. 명산등산로 100(방장산 코드 보충) + 봉우리·갈림길·교통 POI. 지점 병합은 위 ⚠️ 규칙(접두 id, 같은 분류 10m, 같은 자리 GPX 접기).
   코스 지점 = 그 GPX 의 지점(선에서 200m 안) + API 에만 있는 지점(30m 안).
4. 정상 = PEAK 중 이름이 정상·산 이름·괄호 속 봉우리면 우선, 그중 공식 높이에 가장 가까운 것(99산, 대암산만 코스 범위 가운데).
5. 코스 이름 = 들머리(ENTRY·TRANS·PARK·SHELTER·CULTURAL, 300m 안) → 정상(코스 선 200m 안 PEAK) → 끝. 하나뿐이면 "○○ 출발/코스/도착",
   원점회귀는 "○○ ↺ 정상"/"○○ 원점회귀". 버스 ID·날머리 표기는 지운다. 못 만든 코스는 "코스 n"(1차 94 → 2차 45, 아래 §2차).
6. 사진: 산마다 최대 3장을 긴 변 960px JPEG 로 `apps/friendly/data/hiking-images/<산>_<순번>.jpg` 에(2.5MB) — 있으면 다시 받지 않음.

## 계산 규칙 (2차 확정)

- **예상 시간** — 적재 때 조각마다 20m 표본으로 Tobler(1993) 보행 함수 v = 6·e^(−3.5·|경사+0.05|) km/h 를 더해 이동 분
  (`moveMin` 시작→끝, `moveRevMin` 끝→시작). 경사는 ±0.5 에서 자른다(그보다 가파르면 속도가 0 으로 무너진다).
  끊긴 곳은 거리처럼 넣지 않는다. 읽을 때 `@repo/utils estimateHikingMinutes`:
  **예상 = 1.35 × 이동 × (1 + min(이동, 180) / 1500)**(9차 보강에서 다시 맞춤 — 2차 값은 1.12·360·600, §9차 보강) — 보행 배율 +
  길수록 늘어나는 피로·휴식. 짧은 휴식은 들어 있고 점심·긴
  휴식은 없다. 형태별로 summit(코스 최고점에서 끝남)은 왕복(이동 합으로 보정), loop 는 한 바퀴·반대로, traverse 는 이 방향·반대 방향.
  험한 노면 감속은 넣지 않았다 — 노면 범위가 "처음·마지막 나온 곳" 수준이라 구간 감속에 쓸 수 없다.
- **난이도** (`hikingDifficulty`, 나들이 시간 = 왕복 또는 코스 방향 편도):
  - 어려움: 예상 5시간 30분 이상 · 누적 상승 1,000m 이상 · 가장 가파른 500m 평균 55% 이상 중 하나.
  - 쉬움: 예상 3시간 미만 · 누적 상승 500m 미만 · 500m 평균 35% 미만이고 밧줄·릿지·사다리가 없다(암릉·너덜길은 100대 명산
    대부분에 있어 막지 않는다).
  - 그 밖 보통. 607코스 분포(예상 p50 4시간·p90 7시간, 누적 상승 p50 700·p90 1,010m, 500m 경사 p50 40·p90 57%)로 정했고
    결과는 쉬움 43 · 보통 409 · 어려움 154 · 고도 없음 1. 화면에는 그 난이도가 된 까닭(넘은 기준)을 함께 보인다.
- **하산 마감**(3차 확정): 늦어도 출발 = 그날 일몰(들머리 좌표) − 예상 시간(왕복 또는 코스 방향) − 여유 30분. 하산 예상이
  일몰 30분 전보다 이르면 "해 지기 전", 일몰 전이면 "일몰 직전", 넘으면 "해 진 뒤"(`@repo/utils hikingDaylight`).
- **가장 높은 곳 기온**(3차 확정): 들머리 격자 단기예보 기온 − 0.6°C × (코스 최고 고도 − 들머리 고도)/100. 격자의 모델 고도는
  알 수 없어 들머리 기준. 화면에 "추정". 체감은 기상청 겨울철 식(10°C 이하·1.3m/s 이상).

  화면. `Content-Disposition: attachment; filename*=UTF-8<산 이름> <코스 이름>.gpx`, 1시간 공개 캐시.

## 운영 배포

1. `data/open/hiking/` 에 GPX zip 두 개(100대명산 15098177 · 전국 주요 봉우리 15108086)를 올린다(서버에서 자동으로 받지 않는다).
2. `./deploy.sh 4`(또는 2) — 마이그레이션 5건(1차 `add_hiking`·2차 `hiking_time_guide`·3차 `hiking_sigungu`·5차 `hiking_peaks`·9차 `hiking_park`) + `hiking_data` 가
   비어 있으면 적재(1차 100대 명산만일 때 사진 포함 2~3분 — 5차 이후 처음 적재는 아래처럼 30~40분). 다시 적재는 `./deploy.sh 10`. 이미 적재한 서버는 `status:hiking` 의 `stale`(고도는 있는데
   이동 분이 빈 코스 또는 시군구가 빈 코스)이 0 보다 커서 2·4번이 알아서 다시 적재한다 — 그 전까지는 시간·난이도·산불이 비어 보인다.
   시군구는 리포의 `apps/web/public/sigungu-geo.json` 을 읽는다(서버에 있어야 함). 봉우리 zip 을 올렸는데 `status:hiking` 의 `peaks` 가
   0 이어도 다시 적재한다. 처음 적재는 들머리 리·동 역지오코딩(브이월드, 1만 3천 곳 남짓 — 차례로 보내 30~40분, `VWORLD_API_KEY`)과
   봉우리 사진(한 번에 400곳) 때문에 길다 — 역지오코딩 캐시(`apps/friendly/data/hiking-geocode-cache.json`)를 로컬에서 올려 두면 0이 된다. 봉우리 사진은
   `./deploy.sh 10` 을 다시 돌릴 때마다 400곳씩 더 찾는다.
3. 운영 키(DATA_GO_KR_API_KEY)도 명산등산로·산정보·등산트레킹 봉우리·갈림길·교통·**산불위험예보(15084817)** 활용신청이 돼 있어야
   한다(로컬과 같은 키면 됨). 단기예보·에어코리아는 날씨·대기 화면이 이미 쓰는 것.
4. 9차 산행안전지도 — 운영 `apps/friendly/.env` 에 `SAFETYDATA_COURSE_KEY`·`SAFETYDATA_PARK_KEY`·`SAFETYDATA_FACILITY_KEY`(로컬과 같은 값,
   서버 공인 IP 는 safetydata 에 등록함 — 2026-10-26 사용자). 키가 있는데 `status:hiking` 의 `parks` 가 0 이면 2·4번이 다시 적재한다.
   IP 가 막히면(`resultCode 20`) 로컬 `apps/friendly/data/hiking-park/*.json` 을 같은 자리에 올리고 `./deploy.sh 10`.
   9차 보강의 지형 고도 타일은 적재 때 `s3.amazonaws.com` 에서 받는다(215장·8.5MB, 키 없음) — 서버에서 막히면 로컬
   `apps/friendly/data/hiking-dem/` 을 같은 자리에 올린다(없으면 그 41코스만 고도 없이 적재된다).
   `status:hiking` 의 `stale` 은 9차 보강(지형 고도·`reversed` — park JSON 안)을 감지하지 못한다 — 9차를 9차 보강 전 코드로 이미
   적재한 DB 는 `./deploy.sh 10` 으로 손수 다시 적재한다(운영은 아직 9차 전이라 첫 적재에 함께 들어간다).

## 남은 것 / 알려진 문제

- "코스 n" 45코스 — 둘레길·숲길 코스처럼 끝에 이름 붙은 지점이 없다.
- 예상 시간 — 국립공원 공식 소요시간으로 다시 맞췄지만(9차 보강) 공원마다 안내 관행이 달라 코스별 오차는 여전히 크다(중앙 12%,
  ±30% 넘는 곳 있음). 국립공원 밖(산림청·지자체) 안내 표본은 2차 7구간뿐.
- 이정표에서 가는 길·온 길을 못 정한 갈림길 11%(2,783/24,262, 2026-10-26) — 목적지 이름이 코스 지점과 안 맞고 API 이정표라
  방향도 모르는 곳. 공식 구간 이름으로 채우기는 효과가 작아 넣지 않았다(9차 보강).
- 브이월드 2D데이터 `INCORRECT_KEY` 는 Referer 헤더가 원인(5차 조사에서 해결 — 서버 호출은 `Referer: https://ninelife.kr/`).
- 3차: 가장 높은 곳 기온은 격자 모델 고도를 몰라 들머리 기준 추정(실측 비교 안 함). 정상 바람은 격자 값 그대로(문구로 "더 셉니다").
  대기 예보 권역의 경기 남북·강원 영동영서 시군 목록은 추정. 모레 대기는 예보가 없을 때가 많다. 산불 등급 경계값 미확인(면적 그대로).
- 4차: 대중교통은 수도권 밖이면 등산 조사 지점(정류장 이름)뿐 — 노선·시간표 없음. 차로 시간은 길찾기 없는 추정(제주·섬은 배를
  따지지 않음). 크롤 맛집은 들머리 5km 안 산이 3곳뿐이라 대부분 상가정보 음식점(평점 없음). 지도에 추천 순위 표시는 안 함.
  점수 가중치는 우리가 정한 값(실사용 피드백으로 조정).
- 9차: 공식 코스 41개는 지형 고도(SRTM 30m)라 봉우리가 수십 m 낮다. 같은 길 GPX 코스 3개는 공식 구간 순서가 코스 방향과 반대(화면에
  알림, 코스 방향은 GPX 그대로). GPX 코스 중 고도 없는 5개는 그대로. 섬·바닷가 공식 길 5개는 붙일 산이 없어 뺐다.
  팔공산(2023 지정)은 원천에 없다. 탐방로 통제(산불조심기간·자연휴식년)는 이 원천에 없다.
