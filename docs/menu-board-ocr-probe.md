# 메뉴판 통사진 인식 비교 (2026-10-10)

메뉴판 사진 한 장에서 메뉴명·가격을 뽑는 방법을 같은 사진으로 돌려 비교했다. 결론으로 고른 **kimi-k3 + 규칙 프롬프트(OCR 없이)**
는 friendly 에 들어갔다 — 모듈 `apps/friendly/src/modules/menu-board`, 화면 어드민 `테스트 → 메뉴판 읽기`(`/admin/menu-board`),
회귀 평가 `pnpm --filter friendly eval:menu-boards`(검수 정답 `apps/friendly/golden/menu-boards`, 샘플 사진은 `collect:menu-boards`).

> 비교에 쓴 코드(Python 체험 서버 apps/smartly·OCR 엔진·`probe/` 스크립트)와 AI 허브 메뉴판 모델(인식기·번역 모델·메뉴 사전)은
> 2026-10-10 모두 폐기했다. 아래 OCR·하이브리드·메뉴판 AI 숫자는 그때의 기록이고 다시 돌릴 코드는 리포에 없다(커밋 96df0e70 이후 이력에 남음).

## 결론

1. **비전 LLM 이 압도적이다.** 검수 정답 20장 F1 이 비전 LLM 은 73~99%(하이브리드 상위 97~99.8%), 로컬 OCR 엔진(규칙으로 메뉴 묶기)은 25~64%.
   OCR 엔진은 글자 자체는 꽤 읽지만(Surya 이름 정확 77%) 메뉴명·설명·가격·가게 소개를 구분하지 못해, 메뉴가 없는
   사진 4장(표지 3장 + 소스 안내판)에서도 문구 21~37개를 메뉴로 잡았다. 상위 비전 LLM 은 0개.
2. **최종 선택은 ollama cloud `kimi-k3` + 규칙 프롬프트, OCR 없이** — 검수 정답 20장 F1 99.8%(308개 중 307개, 지어냄 0)·
   장당 중앙 약 7초. 프롬프트에 규칙 두 줄(분류 제목 아래 'A 38,000' 은 'LUNCH COURSE A' 로, 떨어져 있는 코스 이름과 가격은 한
   항목으로)을 더하고 사진의 긴 변을 2,000px 로 맞춰(작은 사진은 키워) 넘긴다. Paddle 글자 힌트를 더해도 같은 점수라 OCR 이
   필요 없고, 그래서 GPU·Python 없이 friendly 만으로 된다('최종 선택' 절). friendly 경로로 다시 잰 값은 99.7%.
   더 빠른 쪽은 `gemma4:31b` + Paddle 힌트 + 규칙(99.4%·장당 2.7초)이지만 OCR 이 필요하다 — gemma4 는 힌트가 없으면 92.6%.
3. **Claude Sonnet·Codex(gpt-6.1-sol)도 상위권**(F1 99.2%·98.0%)이지만 CLI 구독 호출이라 서비스 연동에는 API 키가 따로 필요하다.
   Claude 는 장당 약 $0.026 상당·중앙 6.6초, Codex 는 중앙 27.5초·빽빽한 메뉴판 최대 4분 17초로 대화형 화면엔 느리다.
4. **AI 허브 인식기(smartly)를 검출기에 붙인 방식은 가장 낮다**(F1 25~27%). 잘린 메뉴명 한 줄로만 학습해, 검출기가 주는
   단어·설명문 상자와 장식 기호(`*`, `①`)를 엉뚱하게 읽는다. 통사진 용도로는 쓰지 않는다.
5. **생각 모드·검토 한 번 더는 정확도를 올리지 못했다** — gemma4 생각 모드(켬/끔만 받음)는 같은 사진끼리 비교해 단독 96.1 → 94.5%,
   힌트 97.1 → 97.5%, 힌트 + 규칙 99.8 → 99.4% 이고, 장당 3배 느린 데다 60번 중 7번은 5분 넘게 답하지 않았다.
   첫 답을 사진과 대조해 고치게 한 두 번째 호출은 초안을 그대로 돌려줬다. kimi-k3 생각 켬도 검수 20장에선 97.9%(끔 97.4%)·장당 중앙 71초.
   남은 오류는 글자 모양 오독(붓글씨 '청하' → '성하', '쉘크랩' → '웰크랩')이라 추론으로는 안 고쳐진다 — 'gemma4 를 한 단계 올리기' 절.
   대신 kimi-k3 에는 작은 사진을 키워 넘기는 게 듣는다(420×596 손글씨 '논알콜맥주' 오독이 사라짐).
6. ⚠️ 별개로 발견: 영수증 추출 등이 쓰는 `OLLAMA_IMAGE_MODEL=qwen3.5:397b-cloud` 는 **2026-09-25 ollama cloud 에서 퇴역**했다.
   운영 `.env` 포함 교체가 필요하다(이 비교 기준이면 `gemma4:31b` 가 후보).

## 평가 세트

- **캐치테이블 가게 30곳·메뉴판 사진 70장** — friendly `collect:menu-boards` 가 키워드 검색(김치찌개·국밥·칼국수·냉면·삼겹살·
  갈비·돈까스·중식·짬뽕) 결과에서 메뉴판 사진이 있고 메뉴 목록이 5개 이상인 가게를 모았다(가게당 사진 최대 3장).
  인쇄 메뉴판, 벽 메뉴판 사진, 손글씨풍, 메뉴책 촬영, 4개 언어 병기, 메뉴 없는 표지·브랜드 소개가 섞여 있다. 업종이 한식·고기·중식·돈까스에 몰려 있다.
- **검수 정답 20장**(지금은 `apps/friendly/golden/menu-boards`) — 사진을 직접 보고 쓴 메뉴·가격(메뉴 0~50개, 합계 308개). 처음 12장은 서로 다른 가게 12곳에서 한 장씩,
  뒤 8장은 상위 방식(gemma4·kimi-k3 + Paddle, Claude, Codex)의 답이 가장 많이 갈린 사진(4단 빽빽한 중식 메뉴판, 3661×7205 세로로 긴 돈까스
  메뉴판, 408×782 작은 붓글씨 주류표, 코스 메뉴판, 영문 병기 등)을 골랐다. 메뉴 없는 사진 4장(표지 3장 + 소스 안내판, 지어낸 항목 측정)을 넣었다.
  세트 선택지·코스 구성 요리·외국어 병기처럼 뽑아도 틀린 게 아닌 이름은 optional, 묶음 표기('콜라.사이다.환타')는 낱개로 뽑아도 정답.
- **가게 목록(약한 정답)** — 가게가 캐치테이블에 올린 메뉴 목록. 사진에 없는 메뉴(사이드·계절 메뉴)가 섞여 재현율 상한이
  1보다 낮고, 사진에만 있는 메뉴(주류·음료)가 많아 '목록 일치'는 실제 정밀도보다 훨씬 낮다. 그래서 방식 간 차이는
  검수 정답으로 보고, 가게 목록은 70장 전체에서 크게 어긋나는 방식이 없는지 보는 데 쓴다.

## ollama cloud 비전 모델 × Paddle 글자 힌트 순위

ollama cloud 에서 비전을 지원하는 9개 모델을 모두 단독·Paddle 힌트로 70장씩 돌렸다(검수 20장 기준, 힌트 쪽 F1 → 이름 정확 → 속도 순).
규칙 보강 없는 기본 프롬프트끼리의 비교다 — 규칙을 더하면 gemma4 99.4%·kimi-k3 99.8% 로 다시 맨 위('gemma4 를 한 단계 올리기' 절).

- **힌트는 9개 모델 모두에서 F1 을 올렸다**(+0.8~+20.3%p). 약한 모델일수록 크게 오른다 — mistral-large-3 +20.3, minimax-m3 +9.7,

### 프롬프트 v2 — 크기별 가격은 크기마다 한 항목 (2026-10-10)

비교 때의 규칙 '크기·인분별 가격이 여러 개면 첫 번째만'은 정답과 맞추기 쉬운 대신 실제로는 가격을 버렸다 — 네이버 맛집

백골뱅이탕·세트도 첫 크기만 남았다. 규칙을 '크기마다 한 항목, 이름 뒤에 크기를 괄호로("꽃게탕 (대)")'로 바꿨다.

시범·부분 실행(위 표에서 뺌): 검수 20장만 돌린 gemma4 생각 켬·검토 한 번 더·kimi-k3 + 규칙 보강('gemma4 를 한 단계 올리기' 절), kimi-k3 생각 켬(검수 20장 + 시범 3장, 검수 F1 97.9%), glm-5.3-flash(70장 중 26장 실패).

## 틀리는 방식

- **OCR + 규칙**: 가게 소개·슬로건·주소·와이파이 같은 문구를 메뉴로 잡는다(표지 오인 21~37개). 2단·사진 섞인 배치에서 이름과
  가격 행이 어긋나고, 설명문이 이름에 붙는다. 글자를 잘 읽는 Surya 도 F1 64%에 그친다 — 문제는 읽기보다 묶기.
- **AI 허브 인식기**: 장식 기호를 글자로 읽는다('*선지국' → '송선지국'), 긴 설명문 상자는 300×64 로 눌려 깨진다, 대소문자 없음.
- **비전 LLM 오독**: '아게다시도후' → '아계다시도후'(Claude), '태초밥' → '태초초밥'·'치킨난반덮밥' → '치킨난반살밥'·'치타' → '지바'(gemma4),
  '논알콜맥주' → '늦안콜백주'(kimi-k3)·'레몬 슬라이스' → '제로 슬라이스'(Codex) — 둘 다 420×596 작은 손글씨풍 사진. Paddle 글자 힌트를 주면 gemma4 의 이런 오독이 대부분 고쳐진다.
  힌트 + 규칙 보강 뒤에도 남는 gemma4 오독은 Paddle 도 같이 틀린 글자('쉘크랩' → '웰크랩', '레몬웻지' → '레몬윗지')와 작은 붓글씨('청하' → '성하').
- **비전 LLM 범위 실수**: 옵션 안내('특 변경 시 +3,000원')를 항목으로, 묶음 가격의 부속('(라면사리 3,000)')을 빠뜨림.
  분류 제목 아래 'A 38,000' 을 이름 'A' 로(같은 이름이 겹쳐 코스 6개가 4개로 합쳐짐), 코스 이름과 떨어진 1인 가격을 못 묶음 — 규칙 보강으로 고쳐진다.
  세로로 아주 긴 사진(3661×7205)은 긴 변 2,000px 로 줄이면 글자가 작아져 gemma4 단독이 메뉴를 지어낸다(지어냄 47건 중 38건이 이 한 장).
  mistral-large-4 는 표지 문구(가게 이름 유래)를 메뉴로 넣었고, 글자 없는 사진에 JSON 대신 문장으로 답한 1건.
- **텍스트만 묶기(gpt-oss)**: 사진을 못 보니 OCR 이 잘못 자른 행을 그대로 믿고, 표지 문구 일부('JEJU BLACK PORK NO.1')를 메뉴로 넣었다.
