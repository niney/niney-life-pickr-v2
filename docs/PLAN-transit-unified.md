# 대중교통 통합 기능 계획 — "버스+지하철 어떤 것이든" (13~15차)

> 2026-07-07 작성. 커밋 여부는 사용자 지시에 따름(작성 시점 untracked).
> 버스 8차 + 지하철 12차 + D안(지도 풀링)이 완료된 상태를 전제로 한 통합 차수 로드맵.
> 계획 시점의 기록이며, 이후 실제 진행·변경 사항은 커밋 이력이 진실이다.

## Context

버스(/bus)와 지하철(/subway)이 각각 완성돼 대중교통 탭으로 묶여 있으나(뷰포트 이어보기·지도
인스턴스 풀링으로 지도 경험은 이미 연속), 즐겨찾기·주변·검색은 도메인별로 갈라져 있다.
"어떤 것이든 되는 느낌" — 두 도메인을 한 몸처럼 쓰는 경험을 3개 차수로 추가한다.

**사용자 결정 (2026-07-07 확정)**
1. 통합 즐겨찾기 홈: **양 탭 초기화면 공용 섹션** (라우팅 무변경, 별도 홈 탭 없음)
2. 도착 미리보기: **펼침 시에만 로드+폴링** (쿼터 소비가 사용자 의도에 비례)
3. 통합 주변: **양 탭 주변 모드에 상대 도메인 겸표시 + 토글** (신규 화면 없음)
4. 통합 검색: **각 탭 결과에 크로스 섹션 + 상대 탭 딥링크** (검색창·URL 계약 무변경)

**설계 대원칙**: BE 신규 없음 — 세 차수 전부 기존 API·훅의 FE 조합이다(계약 변경 0).
버스 복합 경로 탐색(버스+지하철 환승)은 노선 그래프 적재가 선행돼야 하므로 이번 스코프 제외(장기).

## 13차 — 통합 즐겨찾기 홈 (공용 섹션)

**UX**: 양 탭의 검색 전 초기화면 최상단에 동일한 "즐겨찾기" 통합 섹션. 버스 정류장 /
버스 정류장×노선 / 지하철 역 / 지하철 역×호선이 **한 목록**(도메인 아이콘·색으로 구분,
createdAt asc 병합). 항목 탭 → 펼침(아코디언) → 그때 도착 미리보기 로드+30s 폴링(접으면
enabled=false 로 중단). 항목의 "이동" 액션 → 해당 도메인 탭 딥링크(기존 즐겨찾기 진입 흐름).

**구현**:
- 신규 `apps/web/src/components/transit/TransitFavoritesSection.tsx` — 두 즐겨찾기 훅 조합,
  도메인 태그 유니온 리스트. 펼침 상태는 로컬 state(항목 key 단위, 단일 펼침 권장 — 폴링 1개).
- 기존 도메인별 즐겨찾기 섹션(BusFavoriteSection·지하철 즐겨찾기 영역)을 이 통합 섹션으로
  **대체**(양 탭 중복 노출 방지). 별 토글(BusFavoriteStar 계열)은 각 리스트/패널에 그대로.
- 도착 미리보기: 버스 정류장=arsId 도착 요약(최대 2~3노선), 정류장×노선=해당 노선만 필터,
  지하철 역=상하행 첫 도착, 역×호선=해당 호선만. 항목당 1콜 — 펼친 것만.

**함정/결정 사항**:
- 데스크톱·모바일 레이아웃 **동시 마운트**(CSS 숨김) — 같은 queryKey 라 React Query 가
  dedupe 해 콜은 1회지만, 펼침 state 를 컴포넌트 로컬로 두면 두 인스턴스가 따로 논다 →
  펼침 상태를 모듈 싱글턴 또는 URL 무관 공용 스토어로 승격할지 worker 조사 후 결정
  (transitMapViewport 패턴 참고).
- 버스 가상정류장 arsId='0'은 도착 조회 불가 — 기존 정책(비활성+안내) 재사용.
- 게스트/로그인 하이브리드는 각 훅이 이미 처리 — 조합만.

**검증**: 게스트·로그인 각각, 양 레이아웃, 펼침 시에만 네트워크 발생(개발자도구), 접기 시
폴링 중단, 딥링크 이동, 오늘같이 쿼터 소진일엔 도착 에러 상태 표시 확인.

## 14차 — 통합 주변 겸표시

**UX**: 버스 탭 '내 주변' 모드에서 지하철역 마커가 지도에 함께 표시(호선색 뱃지),
지하철 탭 '내 주변'에선 정류장 마커 겸표시. 토글 칩("지하철역 함께 보기"/"정류장 함께
보기", 기본 on, localStorage 기억). 상대 도메인 마커 클릭 → 해당 탭 딥링크
(`/subway?near=…&stn=…` / `/bus?near=…&stId=…` — 12차 버스 연계 딥링크 계약 재사용).
리스트는 기존(자기 도메인)대로 — 혼합 리스트는 스코프 제외.

**구현**:
- BusStationsMap/SubwayStationsMap 의 markers 배열에 상대 도메인 마커 합류. 마커 id 는
  **명시 prefix**(`x-subway:`/`x-bus:`)로 네임스페이스 분리 — onMarkerSelect 에서 prefix
  감지 시 navigate. 라벨은 겸표시 마커엔 생략(밀도 관리) 또는 줌 임계 재사용.
- 상대 도메인 조회는 주변 모드의 기준점(effectiveNear)과 동일 좌표로 — 재검색/자동
  재조회 시 함께 갱신. 겸표시 마커는 **fit 대상에서 제외**(자기 도메인 결과 기준 화면 유지
  — 마커 배열 순서/별도 소스 중 worker 조사).
- 쿼터: 지하철 nearby=0, 버스 nearby=셀 캐시라 부담 미미(지하철 탭에서 버스 겸표시가
  유일한 추가 소비원 — 셀 캐시 히트가 대부분).

**검증**: 양 탭 주변 모드에서 겸표시·토글·딥링크, 자동 재조회 시 상대 마커 동반 갱신,
따라가기/노선 보기 중엔 겸표시 숨김(집중 모드 기존 정책과 일관), 마커 잔상 없음.

## 15차 — 통합 검색 크로스 섹션

**UX**: 버스 탭에서 "강남" 검색(Enter 제출) → 정류장 결과 아래 "지하철역 N건" 접이식
크로스 섹션(상위 3건 미리보기 + "지하철 탭에서 보기" → `/subway?q=강남`). 지하철 탭도
대칭("정류장 N건" → `/bus?q=`). 크로스 섹션 행 클릭 = 해당 탭 딥링크(선택까지 전달:
`/subway?q=…&stn=…`).

**구현**:
- 각 탭 검색 결과 뷰에 상대 도메인 검색 훅 추가 — **제출된 q 에만 발화**(Enter 제출형
  정책 유지, 라이브 검색 금지). 버스 크로스 검색(지하철 탭)은 30일 캐시 우선이라 쿼터
  부담 낮음.
- 신규 `apps/web/src/components/transit/CrossSearchSection.tsx` (양 탭 공용, 도메인만 주입).
- IME 함정: 검색창 로직 무변경(로컬 state 진실 + URL 미러 기존 패턴 그대로).

**검증**: 양방향 크로스 결과·딥링크(q+선택 전달), 0건일 때 섹션 숨김, 버스 크로스 검색의
source(cache/api) 동작, IME 조합 무손상.

## 공통 리스크·함정

- **데스크톱/모바일 이중 마운트**(hidden xl:flex / xl:hidden) — 새 섹션·훅 전부 양쪽에
  존재. React Query dedupe 로 네트워크는 1회지만 로컬 state 는 인스턴스별 — 공유가 필요한
  상태(펼침, 토글)는 스토어/싱글턴으로.
- **swopen 쿼터**: 도착 미리보기가 유일한 신규 실시간 소비원 — "펼침 시에만" 정책이 방어.
  전량 재관측(verify --fresh) 같은 대량 소비 작업과 같은 날 겹치지 않게.
- 진행 체제: 차수당 worker-fe 1브리프(BE 무변경) → Advisor diff·브라우저 검증 → 사용자
  커밋 지시. 13차 도착 미리보기 실검증은 쿼터 리셋 후(익일)가 깔끔.
