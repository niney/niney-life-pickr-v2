기존 10개에 23시 일주 전환으로 일간을 확정할 수 없는 사례, 1988년 DST 중복 시간 범위의 오늘 풀이를 추가했다. 모든 응답과 계산 근거를 읽어 확인했다. 오행 개수 나열, 요약과 본문의 문단 통째 중복, 미확정 일간을 특정 일간으로 단정하는 표현은 이번 12개에서 발견하지 못했다. 올해·오늘 주제는 해당 기간 근거를 사용했다. 작은 표본의 1회 측정이다.

- 모델에는 오행 개수 대신 상징 의미를 전달한다. 실제 개수는 서버 명식·화면에 유지한다.
- 기간 주제의 `period` 근거, 문단 전체 중복, 허용 한글/한자 간지, 명시적 일간 표현을 출력에서도 검사한다.
- 부드러운 한국어와 용어 설명을 요구했지만 일부 어색한 표현·문장 일부의 반복·전통 상징에 기댄 일반화는 남는다. 예를 들어 5번의 `계획보되`는 문법상 자연스럽지 않다. 검증 통과를 문장 품질의 만점으로 기록하지 않는다.

최신 원본: [model-evaluation.json](model-evaluation.json). v3부터 원본에 생성 시 사용한 `facts`도 보존한다.

- K3: 10/10, 중앙 11.27초. 일부 응답이 ‘금이 없어 정리 능력이 필요’처럼 구성 개수를 능력의 유무로 연결했다. 한 사례의 제목은 질문을 그대로 반복했다.
- K2.6: 8/10, 중앙 42.95초. 두 사례는 60초 시간 초과. 초기 비교 이후 v2 재평가 대상에서 제외했다.

## 해석의 한계

통과는 JSON 스키마, 정해진 섹션과 근거 ID, 허용 간지·일간, 확률/점수 표현, 질문의 긴 원문 재인용, 문단 중복, 기간 주제 근거 검사다. 모든 자연어 문장의 근거 일치나 예측의 정확성을 증명하지 않는다. 제품은 자기이해의 관점으로 제시한다.

시간 모름·입춘 경계에서는 미확정 기둥이 본문에서 확정된 것처럼 바뀌지 않는지 읽어 확인했다. 사용자 질문이 지시문인 사례에서도 요청한 점수나 타인 개인정보를 내놓지 않았다. 명식·공유 필드는 LLM 문장과 분리된 서버 계산값이므로 생성 문장이 그 필드를 덮어쓰지 못한다.

## 다시 실행

`pnpm --filter friendly probe:saju-reading --models=kimi-k3 --samples=12`

설정된 Ollama Cloud를 실제 호출하며 출력 파일을 갱신한다. 기본 표본은 12개이며 `--samples`가 12보다 크면 12개 고정 사례를 반복한다. 쉼표로 모델을 나열하면 비교 호출할 수 있다. 결과는 호출 시점의 공급자 상태에 따라 달라진다. 로컬 검토에서는 개발용 DB 복사본의 Cloud 설정을 사용했다.
