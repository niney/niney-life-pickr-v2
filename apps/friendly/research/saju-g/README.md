# 사주 모델 비교 — 2026-09-06

## 이야기 카드 v4 — 2026-09-07

원국에 `lifeScenes` 세 장면을 추가했다. 최대 출력은 원국 5,000토큰, 기간 풀이 3,500토큰이며 Kimi K3·60초·최대 두 호출을 유지한다. [구현과 검증](../../../../docs/REVIEW-saju-g-stories.md).

합성 사례 12개는 당시 형식·근거 검사에서 12개 모두 통과했다(11개 첫 호출, 일간 미확정 11번은 재시도). 중앙 14.588초, 범위 6.092~34.436초다. 내용 검토에서 **6번의 장면 문장 반복**을 발견했으므로 이를 최종 품질 통과 12/12로 해석하지 않는다. 원본은 [12개 평가](stories-evaluation-v4.json)에 당시 단계와 사후 검토를 함께 기록했다.

미확정 일간의 생활 장면은 `scope`만 인용하도록 제한했다. 여러 장면에 같은 긴 설명 문장을 쓰거나 원국에서 좋은 시기·유리한 날을 판정하는 문구도 거절하도록 보강했다. 후자의 기간 혼동은 중간 재검증에서 발견한 뒤 수정했다. **최종 코드로 문제 사례 6번을 두 번 재검증해 2/2가 첫 호출 통과**했다(16.183초·14.436초). [최종 재검증 원본](stories-target-v4.json). 최종 필터 추가 후 12개 전체를 다시 호출하지는 않았다.

모든 새 생활 장면을 읽어 확인했다. 최종 재검증에서는 해당 문장 반복과 시기 예측이 없었으나, 상징을 실제 성향처럼 말하는 일반화와 일부 응답의 오탈자·비슷한 조언은 남는다. 간단한 문자열·근거 검사는 모든 의미 오류를 걸러내지는 못한다. 사용자 화면에서는 상징을 자신의 경험과 비교할 관점으로 안내한다.

이전 결과를 보존하며 재현: `pnpm --filter friendly probe:saju-g-reading --models=kimi-k3 --samples=12 --output=research/saju-g/new-evaluation.json`. 개별 사례 반복: `--case=6 --samples=2`. 아래 v3 및 궁합 v2 기록과 구분한다.

## 두 사람의 궁합 — 별도 프롬프트 v2

궁합은 `scripts/probe-saju-g-pair.ts`로 별도 평가했다. 같은 오행, 양방향 상생과 상극, 미확정 2개, 관계 4종을 포함한 합성 사례 9개다. `kimi-k3` 9/9가 첫 호출에 출력 검사를 통과했다. 중앙값 10.875초, 최저 8.608초, 최고 15.167초였다. 최대 출력은 3,000토큰이며 개인 사주의 프롬프트 v3와 별도로 버전을 관리한다.

v1 원본 6개에서는 미확정 일간을 연주·월주의 기운으로 대신 설명하는 사례가 있었다. v2부터 모델에는 각 기둥을 제외한 상징·일간 오행 관계·상호 십성·풀이 범위만 전달하고 실제 성격·선호·역할을 임의로 배정하지 않도록 지침을 보강했다. 각 응답을 읽었으며 v2의 8·9번에서 미확정 일간을 다른 기둥으로 대체한 설명은 발견하지 못했다. 3·7번의 역할 예시와 상징 기반 성향 일반화, 문장 일부의 반복, 9번의 `살보며` 같은 오탈자는 남아 있다. 출력 검증이 모든 자연어 문장의 타당성을 보증하지 않는다.

원본: [pair-evaluation.json](pair-evaluation.json), 이전 [pair-evaluation-v1.json](pair-evaluation-v1.json). 원본의 `facts`는 서버 차트 전체이며 v2의 실제 모델 입력에서는 `first/second-year/month/day/hour` 근거를 제외한다. 실행: `pnpm --filter friendly probe:saju-g-pair`. 현재 설정의 Cloud를 실제 호출하고 평가 파일을 갱신한다.

- 모델에는 오행 개수 대신 상징 의미를 전달한다. 실제 개수는 서버 명식·화면에 유지한다.
- 기간 주제의 `period` 근거, 문단 전체 중복, 허용 한글/한자 간지, 명시적 일간 표현을 출력에서도 검사한다.
- 부드러운 한국어와 용어 설명을 요구했지만 일부 어색한 표현·문장 일부의 반복·전통 상징에 기댄 일반화는 남는다. 예를 들어 5번의 `계획보되`는 문법상 자연스럽지 않다. 검증 통과를 문장 품질의 만점으로 기록하지 않는다.

최신 원본: [model-evaluation.json](model-evaluation.json). v3부터 원본에 생성 시 사용한 `facts`도 보존한다.

## 해석의 한계

통과는 JSON 스키마, 정해진 섹션과 근거 ID, 허용 간지·일간, 확률/점수 표현, 질문의 긴 원문 재인용, 문단 중복, 기간 주제 근거 검사다. 모든 자연어 문장의 근거 일치나 예측의 정확성을 증명하지 않는다. 제품은 자기이해의 관점으로 제시한다.

시간 모름·입춘 경계에서는 미확정 기둥이 본문에서 확정된 것처럼 바뀌지 않는지 읽어 확인했다. 사용자 질문이 지시문인 사례에서도 요청한 점수나 타인 개인정보를 내놓지 않았다. 명식·공유 필드는 LLM 문장과 분리된 서버 계산값이므로 생성 문장이 그 필드를 덮어쓰지 못한다.
